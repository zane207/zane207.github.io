systick系统滴答定时器操作总结

一、基础概念
1、全称
SysTick = System Tick Timer 系统滴答定时器
2、归属
ARM Cortex-M3/M4 内核自带定时器，不属于ST公司外设，所有STM32单片机通用
3、核心用处

  1. 精准毫秒级软件延时
    不用依靠循环空耗时间，定时标准，不受主频改动影响；
  2. 嵌入式操作系统（FreeRTOS/UCOS）心跳时钟节拍（暂时不用）
    4、工作原理
    递减计数器：装入初值 → 每个时钟周期数字-1
    数字减到0：触发定时器中断 / 置位标志位；自动重装初值，循环倒计时
    5、时钟来源（F407两种可选）
  3. HCLK/8：系统时钟8分频（推荐，稳定）
  4. HCLK：等于系统主频

二、SysTick 4个核心寄存器
地址全部是内核固定地址，所有Cortex-M内核一致

  1. STK_CTRL：控制状态寄存器（最重要）
    位 功能
    bit0 计数器使能：1=开启倒计时，0=关闭
    bit1 中断使能：1=倒计时到0触发中断；0=只置标志位，不进中断
    bit2 时钟源选择：0=HCLK/8 1=HCLK
    bit16 计数完成标志位：倒计时归0硬件置1，读取自动清零
  2. STK_LOAD：重载初值寄存器
    写入倒计时初始数值，倒计时到0自动加载里面的数字，循环计时
    最大值：2²⁴-1 = 16777215
  3. STK_VAL：当前计数值寄存器
    实时存放正在递减的数字，可读；写入任意数会立刻清空计数器
  4. STK_CALIB：校准寄存器
    初学基本不用。
    寄存器地址宏定义：

#define SysTick_BASE 0xE000E010
#define STK_CTRL *(volatile unsigned int *)(SysTick_BASE + 0x00)
#define STK_LOAD *(volatile unsigned int *)(SysTick_BASE + 0x04)
#define STK_VAL *(volatile unsigned int *)(SysTick_BASE + 0x08)
#define STK_CALIB *(volatile unsigned int *)(SysTick_BASE + 0x0C)

三、模式1：阻塞延时
需求：写一个 void delay_ms(uint32_t ms) 毫秒延时函数
前提：系统主频 SYSCLK = 168MHz，时钟源选择 HCLK/8
时钟节拍频率 = 168M / 8 = 21MHz
每1us需要计数：21个脉冲
每1ms = 1000us → 需要计数：21000 次

步骤1：配置时钟源
设置 SysTick 时钟来源为 HCLK八分频，不使用全速时钟
STK_CTRL &= ~(1 << 2);
步骤2：关闭SysTick内部中断
只读取计时完成标志位，倒计时结束不触发中断
STK_CTRL &= ~(1 << 1);
步骤3：装载1ms计数初值到LOAD寄存器
把1毫秒需要递减的数字写入重载寄存器
STK_LOAD = 21000;
步骤4：延时循环逻辑（单次毫秒延时流程）

  1. 清空当前计数器 VAL，重置倒计时
  2. 打开定时器开关，开始递减计数
  3. 循环等待 bit16 计时完成标志置1
  4. 计时完毕，关闭定时器
    STK_VAL = 0;
    STK_CTRL |= (1 << 0);
    while( !(STK_CTRL & (1 << 16)) );
    STK_CTRL &= ~(1 << 0);
    完整代码+逐行解析
    // 初始化SysTick，配置时钟源
    void SysTick_Init(void)
    {
    // bit2 = 0 时钟源：HCLK/8
    STK_CTRL &= ~(1 << 2);
    // 关闭中断 bit1=0：只查询标志位，不触发中断
    STK_CTRL &= ~(1 << 1);
    // 关闭计数器
    STK_CTRL &= ~(1 << 0);
    }

// ms：要延时多少毫秒
void delay_ms(uint32_t ms)
{
uint32_t i;
// 1ms需要计数21000次
STK_LOAD = 21000;
for(i = 0; i < ms; i++)
{
STK_VAL = 0x00; // 清空当前计数器，立刻重新开始倒计时
STK_CTRL |= (1 << 0); // 开启SysTick计数器

    // 循环等待：bit16计数完成标志置1（倒计时结束）
    while( !(STK_CTRL & (1 << 16)) );

    STK_CTRL &= ~(1 << 0); // 关闭计数器
}

}

总结

  1. STK_CTRL &= ~(1 << 2);
    时钟源选为 168M/8=21MHz，延时最标准通用。
  2. STK_CTRL &= ~(1 << 1);
    关闭中断：我们不用进中断服务函数，全程读取标志位等待即可。
  3. STK_LOAD = 21000;
    装入1毫秒对应的计数数值，每次倒计时跑完刚好1ms。
  4. STK_VAL = 0x00;
    清空当前剩余计数值，强制从头开始倒计时。
  5. STK_CTRL |= (1 << 0);
    打开定时器，开始递减计数。
  6. while( !(STK_CTRL & (1 << 16)) );
    死循环等待，直到倒计时完毕硬件把bit16置1；读取该位后硬件自动清零标志。
  7. 一轮循环走完 = 精准1毫秒。

调用示例
int main(void)
{
SysTick_Init();
GPIO_LED_Init(); // LED初始化

while(1)
{
    LED = 1;
    delay_ms(500);  // 亮500ms
    LED = 0;
    delay_ms(500);  // 灭500ms
}

}

四、模式2：中断方式（定时周期性触发中断）
每隔500ms进一次中断，翻转LED，不需要主循环空等待
步骤1：选择时钟源 HCLK/8
STK_CTRL &= ~(1 << 2);
步骤2：写入定时总计数（例：500ms定时）
STK_LOAD = 21000 * 500;
步骤3：清空当前计数器VAL
STK_VAL = 0;
步骤4：开启溢出中断（倒计时归0触发中断）
STK_CTRL |= (1 << 1);
步骤5：打开定时器总开关，开始循环倒计时
STK_CTRL |= (1 << 0);
配套：固定名称中断服务函数
void SysTick_Handler(void)
{
LED = !LED; //定时时间到执行任务
}
完整代码
// SysTick初始化：开启中断模式
void SysTick_Init(void)
{
STK_CTRL &= ~(1 << 2); // 时钟源 168M/8 =21MHz
STK_LOAD = 21000 * 500; // 500ms重载值
STK_VAL = 0;
STK_CTRL |= (1 << 1); // bit1置1：倒计时到0触发中断
STK_CTRL |= (1 << 0); // 开启计数器
}

// SysTick中断服务函数：函数名固定不可修改
void SysTick_Handler(void)
{
LED = !LED; // 每500ms翻转LED电平
}

代码讲解

  1. STK_CTRL |= (1 << 1);
    开启中断：倒计时归0后，自动向NVIC发送中断请求，CPU跳转中断函数
  2. STK_LOAD = 21000 * 500;
    装载500ms计数值，倒计时结束自动重装数值，永久循环定时
  3. 中断服务函数名固定：SysTick_Handler，内核预设好的
  4. 无需手动清除标志位：SysTick中断硬件自动清零挂起标志，不用像EXTI那样手动写寄存器
    NVIC配置补充（SysTick属于内核中断，无需我们手动配置NVIC）
    SysTick、内核异常中断由ARM内核自动管理优先级，不需要操作NVIC寄存器

五、两种使用方式区别

  1. 查询延时（阻塞）
    主程序卡在while等待，CPU啥事干不了；适合简单点灯延时，初学首选
  2. 中断定时
    CPU主循环可以运行其他任务，时间到自动打断程序翻转LED，实时性更强

六、关键知识点总结

  1. SysTick 是内核自带24位递减定时器，所有STM32通用；
  2. 两大用途：毫秒延时、操作系统时基；
  3. 查询方式：读取CTRL寄存器bit16判断计时完成；
  4. 中断方式：开启bit1，倒计时溢出自动进入中断服务函数；
  5. 时钟源默认选HCLK8分频，延时最精准稳定

七、通俗比喻
SysTick 就是一个倒计时秒表：
设定好倒计时时间 → 按下开始 → 数字一直往下减
数字归零：要么提醒你时间到（查询标志），要么直接喊你过来办事（触发中断）

EXTI外部中断控制器操作总结

一、EXTI基础核心概念

  1. 全称：External Interrupt/Event Controller 外部中断与事件控制器
  2. 作用：持续监控GPIO引脚电平变化，电平跳变后产生信号，交给NVIC内核触发中断
  3. 两条工作模式
    ◦ 中断模式（我们在用）：电平变化→申请中断→CPU停下主程序处理事务
    ◦ 事件模式：仅输出硬件脉冲，不打扰CPU，初学不用
  4. 硬件搭配：EXTI必须依靠 SYSCFG模块 选择哪个GPIO端口接入中断线；必须依靠 NVIC 管理中断优先级、开启中断通道

二、开启外部中断固定6大标准步骤
步骤1：开启外设时钟（所有外设第一步必做）
需要开启2个时钟：
① GPIO端口时钟（按键引脚供电）
② SYSCFG时钟（中断引脚端口映射必备）
// RCC寄存器宏定义
#define RCC_BASE (AHB1PERIPH_BASE + 0x3800)
#define RCC_AHB1ENR (volatile uint32_t)(RCC_BASE + 0x30) // AHB1外设时钟使能
#define RCC_APB2ENR (volatile uint32_t)(RCC_BASE + 0x44) // APB2外设时钟使能

void RCC_Config(void)
{
RCC_AHB1ENR |= (1 << 0); // 位0置1：开启GPIOA时钟
RCC_APB2ENR |= (1 << 14); // 位14置1：开启SYSCFG系统配置时钟
}
总结：单片机外设默认断电休眠，不开时钟硬件完全不工作；SYSCFG和EXTI，缺一不可

步骤2：初始化GPIO引脚（按键输入 + LED输出）
按键引脚：配置为上拉输入；LED引脚：配置为推挽输出
// GPIOA寄存器地址
#define GPIOA_BASE (AHB1PERIPH_BASE + 0x0000)
#define GPIOA_MODER (volatile uint32_t)(GPIOA_BASE + 0x00) // 模式寄存器
#define GPIOA_PUPDR (volatile uint32_t)(GPIOA_BASE + 0x0C) // 上下拉寄存器
#define GPIOA_ODR (volatile uint32_t)(GPIOA_BASE + 0x14) // 输出数据寄存器

void GPIO_Config(void)
{
// 1、PA0 按键：上拉输入模式
GPIOA_MODER &= ~(0x03 << (02)); // 清空PA0两位模式位，设置00=输入模式
GPIOA_PUPDR |= (0x01 << (02)); // 01=开启内部上拉电阻
// 常态：引脚默认3.3V高电平；按键按下引脚接地变0V，产生下降沿

// 2、PA5 LED：通用推挽输出
GPIOA_MODER &= ~(0x03 << (5*2));
GPIOA_MODER |=  (0x01 << (5*2)); // 01=输出模式
GPIOA_ODR &= ~(1 << 5);         // 上电默认LED熄灭

}

步骤3：SYSCFG配置：将中断线映射到指定GPIO端口
EXTI一共16条中断线(Line0Line15)：
Line0统一对应所有引脚0（PA0/PB0/PC0…），需要SYSCFG选定具体端口，这里选PA端口
#define SYSCFG_BASE (APB2PERIPH_BASE + 0x0000)
#define SYSCFG_EXTICR1 (volatile uint32_t)(SYSCFG_BASE + 0x08) // EXTI线03端口选择寄存器

void EXTI_Config(void)
{
// SYSCFG_EXTICR1低4位：配置Line0归属端口
SYSCFG_EXTICR1 &= ~(0x0F << 0); // 先清空原有配置
SYSCFG_EXTICR1 |= (0x00 << 0); // 写入0000：选择GPIOA端口
参数对照：
0000=GPIOA 0001=GPIOB 0010=GPIOC …

步骤4：配置EXTI核心寄存器（触发方式、开启中断）
#define EXTI_BASE (APB2PERIPH_BASE + 0x3C00)
#define EXTI_IMR (volatile uint32_t)(EXTI_BASE + 0x00) // 中断屏蔽寄存器
#define EXTI_FTSR (volatile uint32_t)(EXTI_BASE + 0x0C) // 下降沿触发寄存器
#define EXTI_PR (volatile uint32_t)(EXTI_BASE + 0x14) // 中断挂起标志寄存器

// 1、EXTI_IMR：取消中断屏蔽，允许Line0发送中断请求
EXTI_IMR |= (1 << 0); 

// 2、EXTI_FTSR：开启下降沿触发（3.3V→0V 电平跳变触发中断）
EXTI_FTSR |= (1 << 0); 

// 可选：上升沿触发用 RTSR寄存器，双边沿两个寄存器都置1

}

寄存器作用拆解：

  1. IMR中断屏蔽寄存器：bit=1 允许中断；bit=0 屏蔽中断
  2. FTSR下降沿触发寄存器：bit=1 下降沿触发；RTSR=上升沿触发
  3. PR挂起标志位：中断触发后硬件自动置1，必须软件清零

步骤5：NVIC嵌套向量中断控制器配置（分配优先级、使能中断通道）
EXTI0中断属于内核外设中断，需要NVIC开启通道、设置优先级
// NVIC内核寄存器地址（Cortex-M4内核固定地址）
#define NVIC_ISER0 (volatile uint32_t)0xE000E100 // 中断使能寄存器
#define NVIC_IPR0 (volatile uint32_t)0xE000E400 // 中断优先级寄存器

void NVIC_Config(void)
{
// 1、给EXTI0设置优先级
NVIC_IPR0 &= ~(0xFF << 0);
NVIC_IPR0 |= (0x40 << 0);

// 2、ISER0寄存器：使能EXTI0中断通道，告诉CPU接收该中断
NVIC_ISER0 |= (1 << 6); // EXTI0中断对应第6位

}
规则：
抢占优先级数字越小，优先级越高；高优先级中断可以打断低优先级中断

步骤6：编写中断服务函数（触发中断后执行的代码）
函数名称固定，绝对不能自定义修改，启动文件预先规定好：
EXTI0对应：EXTI0_IRQHandler(void)
uint8_t led_state = 0; // LED状态全局变量

void EXTI0_IRQHandler(void)
{
// 第一步：判断是不是EXTI Line0触发的中断
if(EXTI_PR & (1 << 0))
{
led_state = !led_state; // LED状态翻转
if(led_state)
GPIOA_ODR |= (1 << 5); // LED点亮
else
GPIOA_ODR &= ~(1 << 5); // LED熄灭

    // 重中之重：向PR寄存器对应位写1，清除中断标志位
    EXTI_PR |= (1 << 0); 
}

}
关键要点：

  1. 不清零PR标志：芯片会一直判定中断未处理完毕，无限循环进入中断

  2. 中断函数代码必须简短，禁止长延时、大循环
    主函数：调用所有初始化，循环等待中断触发
    int main(void)
    {
    RCC_Config();
    GPIO_Config();
    EXTI_Config();
    NVIC_Config();

    while(1)
    {
    // 主循环空循环，CPU待机；中断到来立刻跳转中断函数
    }

}

三、完整运行时序流程

  1. 上电依次开启时钟→配置引脚→映射中断线→设置触发方式→配置中断优先级
  2. 空闲状态：PA0上拉为高电平，EXTI无电平变化，CPU运行while(1)
  3. 按下按键：PA0电平3.3V下降至0V，产生下降沿
  4. EXTI检测电平跳变，将PR标志位置1，向NVIC发送中断请求
  5. CPU暂停主循环，自动保存寄存器现场，跳转至EXTI0_IRQHandler
  6. 执行LED翻转代码，手动清除PR中断标志
  7. 退出中断，恢复寄存器现场，回到while(1)继续待机

四、极易踩坑的5个错误点

  1. 忘记开启SYSCFG时钟 → 中断永远无法触发
  2. 触发边沿设置相反 → 按键松开才进中断
  3. 中断结尾未清零PR标志位 → 不间断反复进中断
  4. 中断服务函数名字写错 → 触发中断程序直接跑飞死机
  5. 同一根中断线同时启用两个引脚（PA0+PB0）→ 引脚冲突失效

中断概念笔记

NVIC简介
在讲如何配置中断优先级之前，我们需要先了解下NVIC。NVIC是嵌套向量中断控制器，控制着
整个芯片中断相关的功能，它跟内核紧密耦合，是内核里面的一个外设。但是各个芯片厂商在设
计芯片的时候会对Cortex-M4内核里面的NVIC进行裁剪，把不需要的部分去掉，所以说STM32
的NVIC是Cortex-M4的NVIC的一个子集

EXTI 简介
外部中断/事件控制器(EXTI)管理了控制器的23个中断/事件线。每个中断/事件线都对应有一个
边沿检测器，可以实现输入信号的上升沿检测和下降沿的检测。EXTI可以实现对每个中断/事件
线进行单独配置，可以单独配置为中断或者事件，以及触发事件的属性

一、中断基础概念
1 什么是中断
CPU正在顺序执行主循环while(1)主程序时，当外部引脚电平变化、内部硬件定时器/串口等外设完成工作，会向内核发送中断请求信号
CPU立刻暂停当前运行程序，自动保存寄存器现场，跳转至专门的中断服务函数处理事件；处理完毕后恢复现场，回到被打断的代码位置继续运行

2 中断核心优势

  1. 无需CPU轮询，节约算力
    不用一直循环检测按键、串口是否有数据，硬件主动通知CPU，空闲时CPU可以执行其他任务或进入低功耗休眠；
  2. 实时响应外部事件
    按键按下、数据接收瞬间立刻处理，响应速度远高于轮询扫描；
  3. 支持优先级嵌套
    高优先级中断可以打断正在执行的低优先级中断，紧急事件优先处理
    3 关键限制
    中断服务函数必须精简：禁止长延时、复杂运算、大循环；全局变量要用volatile修饰，防止编译器优化导致数据读取错误

二、STM32中断整体分类
1 外部中断 EXTI(外部中断/事件控制器)
依靠芯片GPIO引脚电平变化触发中断
• 触发条件三类：上升沿、下降沿、双边沿电平跳变；
• 典型用途：独立按键触发中断、外部传感器信号触发唤醒单片机；
• 硬件关联：需要EXTI外部中断线 + SYSCFG寄存器选择引脚映射
2 片内外设中断（内部硬件产生）
单片机内置外设运行结束后自动发起中断请求：

  1. 定时器TIM中断：定时时间溢出触发，用来精准LED闪烁、毫秒计时、脉冲测量；
  2. USART串口中断：收到上位机数据、发送数据完成触发；
  3. ADC转换中断：电压采样结束，通知CPU读取采样值；
  4. DMA搬运完成中断：内存数据搬运完毕触发；
  5. 看门狗中断：用于程序跑飞后自动重启单片机
    3 内核系统异常中断（故障类）
    Cortex-M4内核自带，程序出错时触发，用于调试排查bug：
    硬件故障、总线访问错误、堆栈溢出、内存访问违规等，常规点灯项目几乎不会用到
    4 SysTick 滴答定时器中断
    内核内置24位递减定时器，主要用来做系统毫秒延时、嵌入式操作系统心跳时钟节拍

三、中断两大核心硬件模块（NVIC + EXTI）
1 NVIC：嵌套向量中断控制器（中断总调度中心）
所有中断信号最终都会汇总到NVIC，是内核管理中断的核心部件：

  1. 优先级分组设置
    F407共5种优先级分组，将优先级划分为：抢占优先级 + 子优先级
    • 抢占优先级：决定能否打断别的中断，数值越小优先级越高；
    • 子优先级：同一抢占优先级下，排队先后顺序，不支持中断嵌套；
    初学通用配置：分组2（2位抢占优先级+2位子优先级）
  2. 功能：开启/关闭指定中断通道、分配优先级、响应中断请求、中断现场进出管理
    2 EXTI：外部中断控制器（仅管理GPIO引脚中断）
    专门负责引脚电平中断配置：
  3. 16条外部中断线，每条中断线可映射至对应GPIO端口引脚；
  4. 配置电平触发方式、中断屏蔽开关；
  5. 中断触发后置起挂起标志位，必须软件清零，否则会反复进入中断

四、配置任意中断通用标准步骤（全中断通用流程）
以PA0按键下降沿外部中断举例：

  1. 开启所需外设时钟
    开启GPIOA端口时钟 + SYSCFG系统配置时钟（外部中断必须开启SYSCFG时钟完成引脚映射）；
  2. 初始化GPIO引脚
    引脚设置为输入模式（上拉输入/下拉输入）；
  3. 配置EXTI外部中断参数
    选择引脚对应的中断线、设置下降沿触发、使能中断；
  4. 配置NVIC中断优先级
    设置全局优先级分组，给当前中断分配抢占优先级、子优先级；
  5. 编写中断服务函数
    函数名固定，遵循启动文件预设命名规则；内部编写中断触发后执行逻辑（翻转LED电平）；
  6. 中断末尾清除中断挂起标志位
    必须手动清零标志，否则中断会持续重复触发，造成卡死

五、中断优先级运行规则

  1. 抢占优先级高 → 可以打断正在运行的低抢占优先级中断（中断嵌套）；
  2. 抢占优先级相同，只能排队等待，无法互相打断；
  3. 两个中断同时到来，子优先级高的优先响应。

六、中断优缺点总结
优点

  1. 硬件主动通知CPU，CPU利用率极高；
  2. 事件响应实时性极强；
  3. 可配合休眠模式降低整机功耗，外部信号唤醒单片机。
    缺点
  4. 中断函数代码不能冗长，不能嵌套延时循环；
  5. 多中断并发场景容易出现时序冲突；
  6. 全局变量不加volatile修饰会被编译器优化，读取数据出错；
  7. 优先级设置不当会出现中断无法响应、卡死问题。

七、初学者三大经典实战应用场景

  1. EXTI外部按键中断
    替代轮询按键扫描，硬件触发，彻底解决按键机械抖动问题；
  2. TIM定时器更新中断
    固定周期精准翻转LED，闪烁频率不受系统主频、软件延时影响；
  3. 串口接收中断
    随时接收电脑下发指令，不会丢失串口数据，实现单片机和电脑双向通信。
    一句话收尾
    中断是单片机异步事件处理机制，依靠NVIC统一调度优先级，外部引脚或内部外设均可触发，暂停主程序处理紧急事件，执行完毕后恢复原有程序运行，是嵌入式开发实现实时交互的核心技术。

依托 HSE/HSI 内部时钟配置系统时钟 + MCO输出监控主频

HSE配置系统时钟 + MCO输出监控SYSCLK
整体逻辑顺序
以外部25MHz高速晶振HSE作为时钟源头 → 通过PLL锁相环倍频生成168MHz系统时钟SYSCLK → 配置MCO引脚，将SYSCLK时钟信号引出芯片外部 → 借助示波器测量引脚频率，校验主频配置是否准确无误
分步拆解全过程

第一步：初始化准备，单片机初始状态
单片机上电默认依靠HSI内部16MHz时钟运行，此时尚未启用外部晶振、PLL未开启，主频低速，所有时钟配置寄存器处于上电默认值

第二步：开启并稳定外部高速晶振 HSE

  1. 打开RCC寄存器，使能HSE外部25MHz晶振电路；
  2. 循环等待硬件标志位，直至HSE震荡稳定、输出标准25MHz时钟；
    作用：选用精度最高的外部晶振，作为PLL倍频的基准输入时钟

第三步：配置PLL锁相环全套分频、倍频参数
套用公式：SYSCLK=\frac{HSE}{M}×\frac{N}{P}
经典固定参数：M=25、N=336、P=2、Q=7

  1. 写入PLL配置寄存器，设定分频M、倍频N、主时钟分频P、USB专用分频Q；
  2. 最终算出：系统主频168MHz，同步产出48MHz标准时钟供给USB外设；
  3. 开启PLL模块，等待PLL锁定标志位置1，代表倍频频率稳定输出

第四步：配置FLASH读写等待周期
168MHz属于高频主频，Flash存储器读取速度跟不上CPU运行速度，必须设置5个等待周期；主频更改时，该参数需要同步修改，避免程序运行时序错乱。

第五步：切换系统时钟源为PLL输出时钟
修改时钟切换寄存器，将芯片全局系统时钟SYSCLK，从默认的HSI切换为PLL生成的168MHz高频时钟；自此单片机整体正式以168MHz全速运行

第六步：配置AHB、APB1、APB2三级总线分频
• AHB总线：不分频，HCLK = 168MHz
• APB2高速外设总线：二分频，PCLK2 = 84MHz
• APB1低速外设总线：四分频，PCLK1 = 42MHz
给不同外设分配适配的运行时钟，兼顾运行性能与功耗

第七步：配置MCO引脚，引出系统时钟用于监控

  1. 选用MCO2（PC9引脚），该通道支持输出SYSCLK系统主频；
  2. 将PC9引脚模式设置为复用功能（MCO时钟输出专属模式）；
  3. 配置MCO寄存器：选择时钟源为SYSCLK，设置二分频输出；
    原因：GPIO引脚最高仅支持100MHz信号，168MHz无法直接输出，二分频后引脚输出84MHz波形

第八步：硬件测量、校验时钟（监控环节）
示波器探头接PC9引脚与GND，读取波形频率：
测出频率=84MHz → 证明内部SYSCLK真实为168MHz，整套HSE+PLL时钟配置完全正确；
若频率不符，说明PLL参数、时钟切换代码存在错误

依托 HSI 内部时钟配置系统时钟 + MCO输出监控主频
整体流程逻辑
无需外接晶振，以芯片内部高速RCC时钟HSI（出厂固定16MHz）作为时钟基准 → 送入PLL锁相环倍频，生成目标系统时钟SYSCLK → 配置MCO引脚引出系统主频 → 示波器采集波形，核对实际主频是否和计算值一致，完成时钟校验
逐阶段分步详解

1、上电初始状态
单片机刚上电，默认自动启用 HSI 16MHz 运行，这是出厂默认配置：
没有开启外部HSE晶振，PLL处于关闭状态，内核低速运行，等待我们重新配置整套时钟参数

2、无需开启外部晶振，直接使用HSI当作PLL输入源
和HSE方案最大区别：
HSI是芯片内部集成的RCC振荡电路，不用焊接外部8M晶振、不用等待外部晶体起振稳定，省去HSE开启、等待就绪步骤
缺点：温度变化、电压波动会让16MHz频率轻微偏移，时钟精度远不如外部石英晶振

3、配置PLL分频倍频参数（公式通用）
计算公式依旧：\boldsymbol{SYSCLK=\dfrac{输入时钟}{M} × \dfrac{N}{P}}
输入基准时钟 = HSI = 16MHz
依旧沿用适配USB的经典配套参数：M=8，N=336，P=2，Q=7
代入计算：
16÷8 × 336 ÷ 2 = 336MHz
注意：F407最大允许主频只有168MHz，该参数超标，因此要缩小N值，举例合规配置：
N=168：16/8 * 168/2 = 168MHz（芯片额定最高主频）
同时 Q=7 分频后依旧输出48MHz时钟，满足USB设备时钟要求
参数写入寄存器后，开启PLL，循环等待锁定标志位，直到PLL倍频输出频率稳定

4、配置Flash访问等待周期
主频168MHz高频运行，Flash读取速度跟不上CPU，固定配置：5个等待周期（5WS）
如果降低主频运行，等待周期数值同步下调，防止程序时序紊乱、软件延时失效

5、切换系统时钟源为PLL输出时钟
修改RCC时钟配置寄存器，把全局系统时钟SYSCLK，从原生默认的HSI，切换成PLL倍频后的168MHz时钟
自此单片机整体内核、总线全部按照新主频运行。

6、配置AHB、APB1、APB2总线分频（和HSE方案完全一致）
• AHB(HCLK)：不分频 = 168MHz
• APB2(高速外设)：2分频 = 84MHz
• APB1(低速外设)：4分频 = 42MHz
分级给各类外设分配时钟，平衡性能和功耗

7、配置MCO2（PC9）引脚，输出系统时钟用于监控校验

  1. 开启GPIOC端口时钟，将PC9设置为复用功能模式（MCO时钟输出复用引脚）；
  2. MCO寄存器选择时钟来源：SYSCLK系统主时钟；
  3. 配置二分频输出：GPIO引脚最高承载100MHz信号，168MHz无法直接输出，二分频后向外输出84MHz方波

8、示波器测量校验（监控过程）
示波器表笔接PC9引脚和板子GND：
实测波形频率 = 84MHz，即可证明：
以HSI为源头的整套PLL时钟配置生效，单片机内部准确运行在168MHz主频

HSI方案对比HSE方案核心差异

  1. 优点：脱离外部晶振也可正常配置高频时钟，硬件极简，适合低成本、对时间精度要求不高的场景；
  2. 缺点：时钟精度差、温漂大，长时间运行频率会偏移，不适合串口通信、RTC计时、USB稳定通信场景；
  3. 通用点：PLL计算公式、总线分配、Flash等待周期、MCO输出监控步骤完全相同

一句话精简总结
以芯片内部16MHz高速RC时钟HSI为基准，经过PLL锁相环倍频得到168MHz系统主频，再通过MCO引脚将时钟信号导出芯片，借助示波器测量频率，验证整套内部时钟配置是否正确

RCC时钟树学习笔记

STM32F407 RCC+时钟树
一、基础概念

  1. RCC全称：复位和时钟控制器（Reset & Clock Control）
    作用：掌管芯片所有时钟开启、频率升降、总线分频、外设时钟开关，相当于整个单片机的总电源+调速开关；所有外设（GPIO、定时器、串口）必须开启时钟才能工作
  2. 时钟树：时钟从源头出发，经过分频、倍频、逐级分流，流向CPU、各类总线、外设的完整流向结构图

二、5个原始时钟源头（所有频率的根基）
高速时钟（给CPU、主系统用）

  1. HSI：内部高速RC时钟（16MHz）
    上电默认时钟，芯片内部自带，不用外接晶振；缺点：精度差、温漂大
    上电瞬间单片机先跑这个低速时钟，执行时钟初始化代码，切换到高精度HSE/PLL
  2. HSE：外部高速晶振（标配8MHz）(范围4-26MHz)
    开发板焊接外部石英晶振，精度极高、稳定；配置168MHz主频唯一首选源头
    低速时钟（仅低功耗计时器件使用）
  3. LSE：外部32.768KHz晶振
    专门给RTC实时时钟提供基准，断电靠纽扣电池走时间
  4. LSI：内部低速RC时钟（32KHz）
    精度差，只给独立看门狗、待机唤醒使用
  5. 双PLL锁相环（频率倍增核心模块）
    • 主PLL（PLL）：你一直在配置的模块，把25MHz低频晶振拉升成168MHz高频系统时钟，同时分出48MHz固定时钟供给USB（必须严格48MHz才能识别U盘）
    计算公式：SYSCLK = (HSE ÷ M) × N ÷ P
    经典参数：M=25、N=336、P=2 → (8/8)*336/2 = 168MHz；Q=7专门算出48MHz给USB
    • PLLI2S：音频专用锁相环，播放音乐用，日常点灯几乎用不到

三、时钟主干完整流向
HSE(25MHz) → PLL分频倍频 → SYSCLK(168MHz系统总时钟) → 分成3路总线时钟

  1. SYSCLK：系统总时钟（最高168MHz）
    整个芯片最高频率时钟，供给内核CPU、Flash存储器；可三选一来源：HSI / HSE / PLL输出（我们固定选PLL）
  2. 三级总线分频（RCC->CFGR寄存器配置）
    SYSCLK向下分频，分出3条马路，不同外设分配不同速度，兼顾性能+省电：
  3. HCLK（AHB总线时钟）
    默认不分频：HCLK = SYSCLK = 168MHz
    承载：CPU内核、DMA内存搬运、Flash、高速存储器、以太网等核心硬件，主干道全速跑
  4. PCLK2（APB2高速外设总线）
    二分频：PCLK2 = HCLK ÷ 2 = 84MHz
    承载：GPIO所有引脚、ADC、高级定时器、串口1等高速外设（LED引脚挂载在这里）
    规则：APB2最大上限84MHz。
  5. PCLK1（APB1低速外设总线）
    四分频：PCLK1 = HCLK ÷ 4 = 42MHz
    承载：普通串口、I2C、基础定时器、看门狗等低速外设；上限最高42MHz。
    补充规则：如果APB总线分频系数≥2，挂载上面的定时器时钟会自动翻倍，方便定时计算
    四、外设时钟开关逻辑
    每条总线下面挂载一堆外设，默认全部关闭时钟，必须通过RCC寄存器手动开启对应外设时钟，硬件才会通电工作：
    例：开启GPIOA引脚时钟：RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;
    不开这句，LED引脚初始化完全无效，灯不会亮

五、配套关键硬件设置（代码里的FLASH等待周期）
CPU高速读取Flash里的程序时，Flash硬件速度跟不上168MHz主频，需要设置等待周期（LATENCY）：
• 168MHz：必须配置5个等待周期
• 主频降低，等待周期同步减小，否则程序运行时序错乱、延时无变化

六、上电完整启动流程（对应你的SetSysClock函数执行步骤）

  1. 上电默认跑HSI内部16MHz低速时钟；
  2. 开启外部HSE 25MHz晶振，等待晶振震荡稳定；
  3. 配置PLL的M/N/P/Q参数，算出168MHz主频+48MHz USB时钟；
  4. 开启PLL，等待PLL倍频稳定就绪；
  5. 设置Flash读写等待周期，适配当前主频；
  6. 将系统时钟SYSCLK切换为PLL输出的168MHz；
  7. 配置AHB、APB1、APB2总线分频比例；
  8. 后续main函数里开启GPIO时钟、初始化引脚、点灯循环

七、MCO是什么
MCO = 单片机时钟输出引脚
芯片预留了专门引脚，可以把芯片内部看不见的各种时钟信号引到芯片外面

八、输出监控系统时钟，拆开含义

  1. 系统时钟（SYSCLK）：就是你用PLL配置的168MHz总主频，CPU运行的基准时钟，封在芯片内部，肉眼、万用表都测不到；
  2. 输出：把SYSCLK信号接到MCO引脚上；
  3. 监控：拿示波器接这个引脚，查看波形频率。
  4. 作用（你现在最需要的）
    一次次修改PLL的N数值、调整主频，心里没法确认：
    单片机到底有没有真正跑到 168M / 84M？
    PLL有没有锁定成功？时钟配置写错有没有乱频？
    开启MCO输出SYSCLK之后：
    示波器测出多少赫兹，就代表当前单片机实际主频是多少，用来验证你的时钟代码是否正确

九、F407实操细节

  1. 选用 MCO2（PC9引脚），专门可以输出SYSCLK系统主时钟；
  2. 注意限制：GPIO引脚最高承受100Mhz信号，168MHz超出上限，必须内部二分频输出；
  3. 举例：
    168MHz二分频输出 → 引脚测出来84MHz波形，就证明系统时钟确实是168MHz，配置无误

STM32F407带位操作总结

STM32 位带操作 小白通俗讲解笔记（可直接存入GitHub嵌入式分类）

一、什么是位带？
单片机寄存器都是 32位 的，一个寄存器里面挤了32个引脚电平（每1位代表1个引脚：0低电平、1高电平）
正常写法想单独修改其中某1个引脚：
要先把整个寄存器数值读出来 → 掩码清零目标位 → 赋值1/0 → 写回寄存器，代码繁琐

位带（Bit-Band）就是ST给F1/F4系列单片机设计的快捷机制：
把寄存器里每1个二进制位，单独映射成1个完整32位内存地址
直接给这个专属地址赋值 1 或 0，就能只修改单个引脚电平，不用复杂位运算

举例子：
ODR输出寄存器第6位（PF6引脚），对应一个独立地址
PFout(6) = 1; 直接拉高PF6
PFout(6) = 0; 直接拉低PF6

二、位带两大区域（STM32F4）
单片机内存划分两块支持位带的区域：

  1. 外设位带区：片上所有GPIO、定时器等外设寄存器
    我们点灯、操作引脚只用这一块
  2. SRAM位带区：内存变量
    规则：
    原始1bit（1个位） → 映射别名区占用 4字节（1个32位地址）
    原始1个位带区地址 = 别名区基础地址 + 偏移计算得来

三、位带地址计算公式拆解（你代码里的宏逐句翻译）

  1. 核心计算公式宏

#define BITBAND(addr, bitnum) ((addr & 0xF0000000)+0x02000000+((addr & 0x000FFFFF)<<5)+(bitnum<<2))
代码解释：

  1. addr & 0xF0000000：取出外设寄存器所在大区基地址（外设都是0x40000000开头）
  2. +0x02000000：跳到位带别名区起始地址
  3. (addr & 0x000FFFFF)<<5：原始寄存器整体偏移换算别名区偏移，左移5 = ×32
  4. bitnum<<2：指定要操作的第几位，左移2 = ×4（1位占4字节空间）
    最终算出：某寄存器第bitnum个位 对应的位带别名地址
  5. 指针访问宏

#define MEM(addr) (*(volatile unsigned long *)(addr))
• volatile：强制每次都去硬件地址读取，不被编译器优化（单片机寄存器必备关键字）
• 把数字地址强制转为指针，解引用后可以直接赋值读写
3. 封装整合宏
#define BIT_ADDR(addr, bitnum) MEM(BITBAND(addr, bitnum))
输入：寄存器原始地址 + 要操作的位序号
输出：可直接赋值的位带地址
4. 引脚快捷操作宏（以GPIOF为例）
#define GPIOF_ODR_ADDR (GPIOF_BASE+0x14) //GPIOF输出寄存器地址
#define PFout(n) BIT_ADDR(GPIOF_ODR_ADDR, n)
调用：
PFout(5)=1; 拉高PF5引脚
PFout(5)=0; 拉低PF5引脚

四、传统写法 VS 位带写法对比
需求：把PF6引脚置低电平
老式寄存器写法
GPIOF_ODR &= ~(1<<6);
需要手动用按位取反、与运算，新手很容易写错位数
位带极简写法
PFout(6) = 0;
数字对应引脚号，直观好记，几乎不会出错

五、位带优缺点
优点

  1. 代码极简，读写单个IO引脚超级方便
  2. 可读性极高，新手友好
  3. 底层硬件实现，执行效率很高
    缺点
  4. 仅STM32 F1、F4系列支持；H7、L4等新款芯片取消了位带功能，不能通用
  5. 只能操作：GPIO输出寄存器ODR、输入寄存器IDR、内存变量；其他寄存器场景受限

  1. 开启外设时钟

  2. 配置引脚模式与上下拉

    GPIO_InitStruct.GPIO_Mode = GPIO_Mode_IN;

    原理解析：这里将 PA0 和 PC13 配置为输入模式
  • 关键工程提醒： GPIO_PuPd_NOPULL（浮空输入），根据野火的理论总结：“硬件电路上，按键通常配合上拉或下拉电阻使用，目的是避免引脚悬空导致状态混乱”

  1. 阻塞式等待（松手检测）
  • while(GPIO_ReadInputDataBit(…) == KEY_ON); 这是一个阻塞式（Blocking）的死循环

这次做寄存器映射中的结构体映射
结构体映射要从：
1.定义基础类型
2.建立结构体映射
3.用指针配合结构体
4.使用 BSRR 寄存器来拉高/拉低电平

一、 为什么要定义基础类型（typedef）？
代码片段：
typedef unsigned char uint8_t;
typedef unsigned int uint32_t;
原因：跨平台与硬件的“绝对对齐”

  1. C语言的“不严谨”：在标准 C 语言中，int 到底是 16位、32位还是 64位，取决于你的编译器（比如 PC 上的 GCC 和单片机上的 ARMCC 是不同的）。
  2. 硬件的“强迫症”：STM32 的寄存器是严格的 32位（4字节）或 8位。如果你用 int 去操作一个本该是 32位的寄存器，在某些编译器下可能只分配了 16位，导致你写入的数据被截断，或者覆盖了旁边的其他寄存器。
  3. 结论：通过 typedef 强制规定 uint32_t 就是 32位无符号整数，确保代码在任何编译器下，对内存的读写长度都是绝对一致的

二、
为什么要用结构体（struct）来映射寄存器？
代码片段：
typedef struct {
volatile uint32_t MODER; // 偏移 0x00
volatile uint32_t OTYPER; // 偏移 0x04
// …
} GPIO_RegDef_t;
原因：将“冰冷的地址”变成“有逻辑的变量”

  1. 内存的连续性：STM32 的 GPIOA 的所有寄存器在物理内存中是紧挨着的（从 0x40020000 开始，每隔 4 个字节一个）。C 语言的结构体在内存中也是连续分配的
  2. 告别魔法数字（Magic Number）：
    • 如果不用结构体，你要配置模式，得写：(volatile uint32_t)(0x40020000 + 0x00) = xxx;
    • 配置速度得写：(volatile uint32_t)(0x40020000 + 0x08) = xxx;
    • 这种代码极难维护，一旦基地址变了，要改几十处
  3. 结构体的优雅：定义好结构体后，编译器会自动帮你计算偏移量。你只需要写 pGPIOx->OSPEEDR = xxx;，编译器会自动翻译成 基地址 + 0x08。代码可读性极强，且完美契合芯片手册的寄存器表格
    关键补充：volatile 关键字的作用
    注意结构体里的 volatile。它告诉编译器：“这个变量的值可能会在程序之外被改变（被硬件改变），请不要自作聪明把它优化到 CPU 寄存器里，每次都必须老老实实去内存（物理地址）里读取！” 如果没有它，你的代码在开启编译优化（如 -O2）时会彻底失效

三、 为什么要用指针（Pointer）？
代码片段：
define GPIOA ((GPIO_RegDef_t*)GPIOA_BASE)
void My_GPIO_Init(GPIO_RegDef_t *pGPIOx, GPIO_InitTypeDef *pGPIOInit);
原因：实现代码的“高度复用”

  1. 硬件的对称性：STM32 有 GPIOA, GPIOB, GPIOC… 它们的内部寄存器结构（MODER, OTYPER等）是一模一样的，仅仅是基地址不同
  2. 指针的魔力：如果我们把函数的参数写成 GPIO_RegDef_t *pGPIOx（一个指向 GPIO 结构体的指针），那么：
    • 传 GPIOA 进去，它就操作 GPIOA 的寄存器
    • 传 GPIOB 进去，它就操作 GPIOB 的寄存器
  3. 结论：通过指针，你只需要写一套初始化函数，就能控制芯片上的几十个 GPIO 端口。这就是底层驱动框架设计的核心思想。

四、 为什么要用 BSRR 寄存器来拉高/拉低电平？
代码片段：
// 拉高：低 16 位置 1
GPIOA->BSRR = (1 BSRR = (1 ODR |= (1 ODR 步骤2：在 CPU 内部修改第 14 位 -> 步骤3. 把新值写回 ODR))))
如果在步骤2和步骤3之间，发生了中断，并且中断里也修改了 GPIOA 的其他引脚，那么中断返回后，步骤3.会把中断里的修改直接覆盖掉！这就叫“非原子操作”，极易引发隐蔽的 Bug
2. BSRR 的完美设计（原子操作）：
BSRR（Bit Set/Reset Register）是一个只写寄存器，硬件为它设计了特殊的逻辑：

  • 低 16 位 (0~15)：写 1 会将 ODR 对应位置 1（拉高），写 0 无效
  • 高 16 位 (16~31)：写 1 会将 ODR 对应位置 0（拉低），写 0 无效

优势：你只需要一条赋值语句（一条汇编指令 STR），硬件直接在内部完成“置位”或“清零”，不需要读-改-写的过程。这被称为原子操作，即使在最高优先级的中断里操作 BSRR，也绝对不会影响其他引脚的状态

总结：

  • 基础类型保证了数据宽度的绝对正确；
  • 结构体把物理地址变成了优雅的代码；
  • 指针让一套代码控制了所有外设；
  • BSRR 则利用硬件特性，保证了电平翻转的绝对安全与高效

STM32f407GPIO寄存器实操笔记

第一
1、片上外设基地址
ST生产STM32的时候，给芯片里面所有外设安排独一无二的地址，就像每家的门牌号。
所有外设统一从 0x40000000 开始，这个把它取为：PERIPH_BASE
#define PERIPH_BASE ((unsigned int)0x40000000)
理解：整个小区大门地址：0x40000000
2、区分不同总线：AHB1总线偏移
芯片内部有好几条“（总线）”
GPIOA/GPIOB/GPIOF全部跑在 AHB1
厂家规定：AHB1 = PERIPH_BASE + 0x20000
#define AHB1PERIPH_BASE (PERIPH_BASE + 0x00020000)
理解：AHB1这条街道入口 = 大门往里走0x20000
3、GPIOA的门牌号
GPIOA就在AHB1街道最开头，偏移0，所以：
#define GPIOA_BASE (AHB1PERIPH_BASE + 0x0000)
GPIOF是 AHB1PERIPH_BASE + 0x1400，相当于同一条街往后走一段距离。
4、GPIOA里面一堆寄存器，靠【偏移量】区分
找到GPIOA大门（GPIOA_BASE）之后，门里面有一排连续房间，每个房间对应一个寄存器：
厂家手册固定死偏移：
• MODER 模式寄存器：进门第0间 → +0x00
• OTYPER 输出类型：第1间 → +0x04
• OSPEEDR速度寄存器：+0x08
• PUPDR上下拉：+0x0C
• IDR输入寄存器：+0x10
• ODR输出寄存器：+0x14
• BSRR置位/复位寄存器：+0x18
代码里这句含义：
#define GPIOA_MODER (unsigned int)(GPIOA_BASE+0x00)

  1. GPIOA_BASE+0x00：算出MODER房间地址
  2. (unsigned int *)：把数字强行变成地址指针
  3. 最前面*：代表去这个地址里面读写数据

第二：2*5、1<<5 这些数字怎么来（PA5引脚）
每个引脚都分配固定的bit位置
1.MODER、OSPEEDR、PUPDR：每个引脚占用 2个bit！！重点！
PA0 → bit0、bit1
PA1 → bit2、bit3
PA2 → bit4、bit5
……
PA5 → bit10、bit11
计算公式：引脚编号 × 2
PA5：5 * 2 =10，从第10位开始占用两位
GPIOA_MODER &= ~((unsigned int)0x3 << (2 * 5));
0x3 = 二进制11，代表连续两个1；向左移10位，刚好对准PA5的两个bit。

2.OTYPER、BSRR、IDR、ODR：每个引脚只占用 1个bit
PA5就只用第5号位，不用乘2
GPIOA_OTYPER &= ~(0x1 << 5);
GPIOA_BSRR |= (1 << 5);
1 << 5 = 二进制 100000，第5位是1，精准选中PA5

3.BSRR特殊规则（一定要记住）
• 低16位（bit015）写1 → 引脚变高电平
• 高16位（bit1631）写1 → 引脚变低电平
PA5拉低写法：1 << (16+5)

第三点：函数里每一步的逻辑通俗解释
RCC_AHB1ENR |= (1 << 0);
RCC是时钟总开关。GPIOA挂在AHB1第0位。
= 给GPIOA“通电”，不通电寄存器全部失灵，相当于设备没插电。
GPIOA_PUPDR |= ((unsigned int)0x01 << (2 * 5));
01=内部上拉。PA5上电默认被内部电阻拉到3.3V；
如果你不想上下拉，就只写清零那一行，不要加这一句。
PA5 普通引脚：随便配置，不用额外代码
PA13 PA14 PA15：出厂默认分给下载器JTAG，就算地址代码写对，硬件会抢控制权，必须SYSCFG解除占用，PA5没有这个麻烦！
极简记忆口诀

  1. 地址：大门基地址 + 寄存器固定偏移
  2. 2bit寄存器(MODER/速度/上下拉)：移位 = 引脚×2
  3. 1bit寄存器(OTYPER/BSRR)：直接 1 << 引脚号
  4. 第一步永远先开时钟！不开时钟一切配置白费
    整体代码：

/*总线基地址 */
#define AHB1PERIPH_BASE (PERIPH_BASE + 0x00020000)

/GPIO外设基地址/
#define GPIOF_BASE (AHB1PERIPH_BASE + 0x1400)
/GPIO外设基地址/
#define GPIOA_BASE (AHB1PERIPH_BASE + 0x0000)

#define GPIOA_MODER (unsigned int)(GPIOA_BASE+0x00)
#define GPIOA_OTYPER (unsigned int)(GPIOA_BASE+0x04)

#define GPIOA_PUPDR (unsigned int)(GPIOA_BASE+0x0C)
#define GPIOA_IDR (unsigned int)(GPIOA_BASE+0x10)
#define GPIOA_ODR (unsigned int)(GPIOA_BASE+0x14)
#define GPIOA_BSRR (unsigned int)(GPIOA_BASE+0x18)

以上可视为函数库

写寄存器代码的前提 第1行：RCC_AHB1ENR |= (1 << 0);
课本知识没有写，但一切GPIO的前提
GPIO相当于电器，时钟=电源。不开时钟，后面所有寄存器全部失效。
GPIOA在AHB1时钟寄存器第0位，写1=通电。

第四. GPIOA_MODER（模式寄存器）
理论规则：
MODERy[1:0]
00：输入（上电默认）
01：通用输出
10：复用功能
11：模拟输入
代码：
GPIOA_MODER &= ~((unsigned int)0x3 << (2 * 5));
GPIOA_MODER |= ((unsigned int)0x1 << (2 * 5));

  1. PA5，y=5；MODER每个引脚占用2位 → 移位 2*5=10
  2. 0x3 = 二进制 11
    &= ~(0x3 <<10)：先把PA5对应的两位清0，清除上电默认配置
  3. 0x1 = 二进制 01，写入进去
    最终效果：PA5 设置【通用输出模式】

第五. GPIOA_OTYPER（输出类型寄存器）
理论规则：
0：推挽输出（复位默认）
1：开漏输出
代码：
GPIOA_OTYPER &= ~(0x1 << 5);
OTYPER每个引脚只占1个位，直接1<<引脚号
~(1<<5) 把第5位清0
PA5配置成【推挽输出】
推挽：能主动输出3.3V高电平、0V低电平，最常用驱动LED

第六. GPIOA_OSPEEDR（输出速度寄存器）
理论规则：
00：2MHz
01：25MHz
10：50MHz
11：100MHz
代码：
GPIOA_OSPEEDR &= ~((unsigned int)0x03 << (2 * 5));
GPIOA_OSPEEDR |= ((unsigned int)0x00 << (2 * 5));
OSPEEDR和MODER一样，每个引脚2位，移位 = 引脚×2
先清零两位，再写入00
PA5 最大速度 2MHz（低速）
日常点灯用低速足够，省电、噪声小

第七. GPIOA_PUPDR（上下拉寄存器）
理论规则：
00：无上下拉
01：上拉
10：下拉
11：保留
代码：
GPIOA_PUPDR &= ~((unsigned int)0x03 << (2 * 5));
GPIOA_PUPDR |= ((unsigned int)0x01 << (2 * 5));
PUPDR依旧是每个引脚占用2位
先清零，写入二进制01
PA5开启【内部上拉电阻】
小提醒：输出模式开上拉一般很少用，输入模式用得多。如果只是驱动LED，可以删掉这一行，改成只清零 GPIOA_PUPDR &= ~((unsigned int)0x03 << (2 * 5)); 设置成无上下拉

第八. GPIOA_BSRR（置位/复位寄存器）
理论规则：
BSRR低16位 BSy：写1 → 引脚置高电平
BSRR高16位 BRy：写1 → 引脚置低电平
代码：
GPIOA_BSRR |= (1 << 5);
1<<5，对应BS5位写1
PA5立即输出高电平（3.3V）

如果想要拉低，写法：
GPIOA_BSRR |= (1U << (16 + 5));
重点区分 BSRR 和 ODR

BSRR 优势：只修改指定引脚，不会影响其他IO，强烈推荐；
不要直接写 GPIOA_ODR，多任务下容易冲突。
整体总结：这段代码最终配置结果

PA5：通用推挽输出、2MHz低速、内部上拉、上电直接输出高电平

万能公式
MODER / OSPEEDR / PUPDR（2位寄存器）
寄存器 &= ~(0x3 << (2 * 引脚号)); //清空
寄存器 |= (值 << (2 * 引脚号)); //写入配置
OTYPER / BSRR / IDR / ODR（1位寄存器）
寄存器 &= ~(1 << 引脚号);
寄存器 |= (1 << 引脚号);

易错点
PA13、PA14、PA15：硬件默认JTAG调试功能
MODER配置会被硬件强行覆盖，就算代码写的一模一样，引脚不受控制，必须用SYSCFG解除复用
PA5/PA0~PA12：普通引脚，直接这套代码就能正常运行，没有额外限制

整体代码：
void PA5_Init_F407_Reg(void)
{
/* 1. 开启 GPIOA 时钟 (AHB1ENR 的第 0 位) */
RCC_AHB1ENR |= (1 << 0); 

/* 2. MODER寄存器 配置PA5 */
GPIOA_MODER &= ~((unsigned int)0x3 << (2 * 5)); 
GPIOA_MODER |= ((unsigned int)0x1 << (2 * 5));  

/* 3. OTYPER 输出类型 */
GPIOA_OTYPER &= ~(0x1 << 5); 

/* 4. OSPEEDR 输出速度 */
GPIOA_OSPEEDR &= ~((unsigned int)0x03 << (2 * 5));
GPIOA_OSPEEDR |= ((unsigned int)0x00 << (2 * 5)); 

/* 5. PUPDR 上下拉配置 */
GPIOA_PUPDR &= ~((unsigned int)0x03 << (2 * 5));
GPIOA_PUPDR |= ((unsigned int)0x01 << (2 * 5));   

/* 6. BSRR 设置PA5输出高电平 */
GPIOA_BSRR |= (1 << 5);

while(1);

}

C语言运算知识

一.原码，反码，补码
电脑/单片机只认识二进制 0 和 1，数字分正数、负数，机器靠最高一位区分正负：
最高位=0 → 正数
最高位=1 → 负数
我们拿1字节（8位二进制）举例，好理解。

  1. 原码：给人看得懂的写法
    规则：
    最高位符号位，后面正常写数字二进制。
    举例8位：
    +5：00000101 （0代表正数）
    -5：10000101 （1代表负数）
    缺点：
    0有两种写法：00000000（+0）、10000000（-0），重复浪费空间
    计算机做减法巨麻烦，硬件不好计算，所以机器不用原码运算

  2. 反码：过渡产物，只为算补码用
    规则：
    正数：反码 = 原码（不变）
    负数：符号位不动，剩下所有0变1、1变0
    还用8位举例：
    +5 原码：00000101 → 反码不变：00000101
    -5 原码：10000101 → 符号1不动，后面取反 → 11111010
    缺点：
    0还是有两个表示，依旧不能直接拿来做减法，只是中间步骤。
    3=（-2）= 00000011+11111101=1 000000000（多一位）

  3. 补码：计算机真正存数字、算数字的格式（重点！）
    规则
    正数：补码 = 原码 = 反码，全程不变
    负数：负数反码 + 1 = 补码
    举例 -5
    原码：10000101
    反码：11111010
    反码+1 → 补码：11111011

为什么一定要用补码？两大好处
解决0重复问题，8位二进制只有一个0：00000000
举个例子：计算 5 - 3 = 5 + (-3)
5补码：00000101
-3补码：11111101
两者相加：00000010 也就是2，计算正确！

极简记忆口诀
原码：人看的，正负分开写
反码：负数符号不动，其余全部翻转
补码：正数原样，负数反码加1；电脑存数字、算加减全靠它因此计算机内部用补码=

二.位运算与位运算符
单片机、电脑里所有数字底层都是二进制0、1
位运算 = 直接操作整数类型的二进制里每一个0和1，嵌入式写寄存器、控制引脚

位运算符有6个

  1. 按位与 & （符号：和）
    规则：两位同时为1，结果才是1；只要有一个0，结果就是0
    口诀：全1才1，有0则0
    例：3 & 1
    3二进制：00000011
    1二进制：00000001
    结果：00000001 = 1
    嵌入式用途：清零某一位、读取寄存器某一个引脚状态

  2. 按位或 | （符号：竖线）
    规则：任意一位是1，结果就是1；全0才是0
    口诀：有1则1，全0才0
    例：3 | 1
    00000011 | 00000001 = 00000011 =3
    嵌入式用途：把指定某一位置1（拉高引脚电平）

  3. 按位异或 ^
    规则：两位不一样=1，两位相同=0
    口诀：相同出0，不同出1
    例：3 ^ 1
    00000011 ^ 00000001 = 00000010 =2
    用途：翻转指定二进制位、简单加密、交换数字不用第三方变量

  4. 按位取反 ~ （单目运算符，只写在数字前面）
    规则：所有0变1，所有1变0，符号位也一起翻转
    例：char a=3（00000011）
    ~a 全部翻转 = 11111100
    重点：单片机char是有符号数，最高位1代表负数，取反后会变成负数。
    用途：批量清零多位寄存器

  5. 按位左移 <<
    格式：数字 << 移动位数
    规则：二进制整体往左挤，右边空出来补0，左边挤出去的数字直接丢掉
    例：1 << 2
    1：00000001
    左移2位：00000100 等于4
    隐藏技巧：左移n位 = 数字 × 2的n次方

  6. 按位右移 >>
    格式：数字 >> 移动位数
    分两种情况：

  7. 正数：整体右挤，左边补0

  8. 负数（补码存储）：整体右挤，左边补1
    例：4 >> 1
    4：00000100 → 右移1位 00000010 =2
    —4 >> 1
    —4：11111100 → 右移1位 11111110 =—2
    隐藏技巧：右移n位 = 数字 ÷ 2的n次方（取整数）

嵌入式最常用组合操作（写寄存器必用）

  1. 某一位置1：a |= (1<<n)
  2. 某一位清零：a &= ~(1<<n)
  3. 翻转某一位：a ^= (1<<n)
    总结
  4. & 留1清0；| 统一置1；^ 相同归零
  5. ~ 全部翻转；<< 左移翻倍；>> 右移减半
  6. 单片机控制引脚、配置寄存器全部靠位运算，不会改动其他引脚，精准控制单独某一位

三.复合赋值运算符

普通写法：a = a + 数字
意思是：拿a本身的值，加上一个数，算完之后，结果重新存回a里面。
复合赋值就是把这行代码简写，少敲重复的a，写单片机代码经常用。
复合赋值运算符:将运算和赋值合并为一步的简写方式
逐个讲常用6种，配简单例子
我们统一设初始值：int a = 5;

  1. 加法复合 +=
    简写 a += 3 等价完整写法 a = a + 3
    计算：5+3=8，最后a=8
  2. 减法复合 -=
    简写 a -= 2 等价 a = a - 2
    初始a=5，5-2=3，最后a=3
  3. 乘法复合 *=
    简写 a = 4 等价 a = a * 4
    5    4=20，a变成20
  4. 除法复合 /=
    简写 a /= 2 等价 a = a / 2
    5÷2=2（整数只留整数部分），a=2
  5. 取余复合 %=
    简写 a %= 2 等价 a = a % 2
    5除以2余1，a=1
  6. 位运算复合（单片机写寄存器天天用！重点）
  7. a |= (1<<2) 等价 a = a | (1<<2) 单独把第2位置1
  8. a &= ~(1<<3) 等价 a = a & ~(1<<3) 单独把第3位清零
  9. a ^= (1<<1) 等价 a = a ^ (1<<1) 翻转第1位电平
  10. a <<= 1 等价 a = a << 1 左移一位翻倍
  11. a >>= 1 等价 a = a >> 1 右移一位除以2

核心记忆口诀
符号= 等于 自己 符号 数字
举个万能模板：a OP= b ↔ a = a OP b
OP就是 + - * / % & | ^ << >> 任意运算符

易错点

  1. 复合运算符中间不能加空格，不能写成 a + = 3，正确 a +=3
  2. 等号永远在运算符右边，顺序别写反，没有 =+ 这种写法！

嵌入式实用例子（控制引脚）
unsigned int GPIOA = 0;
GPIOA |= (1<<15); // PA15引脚置高
GPIOA &= ~(1<<15); // PA15引脚清零
用复合写法代码更短，是写STM32寄存器标准写法。
