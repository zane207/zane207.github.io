DMA知识总结

DMA简介
DMA全称：Direct Memory Access 直接存储器访问
核心意义：数据搬运全程不需要CPU参与，硬件自主完成数据传输，解放CPU内核去执行其他任务

一、通道 + 流（Stream + Channel）
名词区分
Stream（流）：DMA最小独立传输单元；DMA1、DMA2控制器各自拥有 Stream0 ~ Stream7 共8条流
Channel（通道）：属于流内部的外设路由选择。每一条流拥有8个通道选项，用来绑定不同外设的DMA请求信号
完整工作原理
STM32片内外设（USART、ADC、SPI、TIM）在需要DMA搬运数据时，会输出DMA请求信号REQ

  1. 我们代码配置：选择某一条Stream，并且配置该Stream的通道，把外设请求路由接入这条流；
  2. 同一时刻，一条Stream只能选择一个通道，只能服务一个外设
  3. 多个外设想要同时DMA传输，必须分配到不同的Stream
    通俗类比
    流 = 8条独立高速公路；通道 = 高速路的出入口，不同出入口连接不同外设（串口、ADC等）
    通道只是‘信号路由开关’，不具备独立传输能力；真正负责传输的硬件实体是「流」

二、仲裁器 Arbiter
工作原理
当多条Stream同时产生DMA传输请求，多条数据流想要抢占内部总线资源，此时仲裁器负责调度次序，防止总线冲突
仲裁优先级判定顺序：

  1. 软件配置优先级（4档：高 > 中 > 低 > 极低）；
  2. 如果软件优先级相同，Stream编号越小优先级越高（Stream0 > Stream1 > … > Stream7）。
    工作流程：
    多个Stream把请求送入仲裁器 → 仲裁器对比优先级 → 允许优先级最高的流占用内部总线访问FIFO；
    当前流传输一小段结束后，再切换下一个等待的流。
    类比：高速路口交警，多条车道同时想要通行，交警按照优先级放行。

三、FIFO 先进先出缓冲区（First In First Out）
F4每条Stream内置 4级深度FIFO，可开启/关闭（关闭即直接模式）
工作原理
核心解决【外设速度】和【存储器访问速度不匹配】的矛盾。
场景举例：串口慢速逐字节收到数据，内存适合批量读写。

  1. 开启FIFO模式
    外设逐字节数据先存入FIFO缓存，积累到设定阈值之后，一次性批量搬运到内存；减少频繁总线请求，提升传输效率。支持数据打包、数据位宽转换
  2. 关闭FIFO（直接模式）
    不缓存，外设收到1个字节立刻发起一次内存搬运。适合少量实时数据传输，不支持打包
    限制：内存到内存（Memory-to-Memory）传输强制只能使用直接模式，无法开启FIFO

四、存储器接口 Memory Port
工作原理
物理上连接DMA内部总线与系统AHB总线，负责访问芯片存储区域：SRAM、Flash
DMA传输两种流向：

  1. 存储器 → 外设：内存的数据，经过存储器接口送入DMA，最终发往串口/SPI等外设；
  2. 外设 → 存储器：外设采集的数据，经过DMA，通过存储器接口写入SRAM缓冲区
    所有读写内存的脉冲、地址信号、数据信号都由这个接口产生，全程无需CPU控制

五、外设接口 Peripheral Port
工作原理
作为DMA和各个片内外设（USART、ADC、TIM、SPI）之间的数据桥梁。

  1. 外设产生数据后，把数据送到外设接口；
  2. 或者DMA把数据通过外设接口推送给外设进行发送；
  3. 外设发出的DMA硬件请求信号，也通过这条线路送到前面的「流、通道」模块
    区分：外设接口只管和片上外设通信；存储器接口只管和内存通信。

六 、编程接口（AHB从设备接口）
工作原理
DMA控制器在系统里被当做一个AHB从设备
CPU（内核）通过这条AHB接口，读写DMA全部寄存器：

  • CCR：通道配置寄存器
  • CNDTR：剩余数据数量寄存器
  • CPAR：外设地址寄存器
  • CMAR：存储器地址寄存器
    我们在Keil编写代码调用 DMA_Init() 函数，本质就是CPU通过这个接口，向DMA硬件写入配置参数，设置传输方向、数据宽度、地址、传输长度
    DMA配置完成后，CPU就可以退出，不再参与后续数据搬运。

完整数据流串联演示（ADC采集，DMA搬运数据到内存）

  1. ADC完成一次采样，发出DMA请求信号；
  2. 请求信号根据通道配置，路由到指定Stream；
  3. 如果多个Stream同时请求，仲裁器根据优先级调度；
  4. ADC采样数据通过【外设接口】送入DMA；
  5. 数据存入FIFO缓冲；
  6. 达到阈值后，通过【存储器接口】，自动把数据写入SRAM；
  7. 整个搬运过程CPU不介入；CPU只需要后续去SRAM读取结果。

核心总结

  1. 通道=外设路由，流=独立传输通道；
  2. 仲裁器解决多流并发资源争抢；
  3. FIFO解决外设与内存速度不匹配，实现批量传输；
  4. 外设接口 ↔ 片内外设；存储器接口 ↔ SRAM/Flash；
  5. 编程接口是CPU用来初始化、配置DMA寄存器的通道。
