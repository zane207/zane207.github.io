配置DMA由M-M和M-P的代码总结

一、DMA_InitTypeDef 初始化结构体逐成员详解
typedef struct
{
uint32_t DMA_Channel; // 通道选择
uint32_t DMA_PeripheralBaseAddr; // 外设基地址
uint32_t DMA_Memory0BaseAddr; // 存储器0基地址
uint32_t DMA_DIR; // 传输方向
uint32_t DMA_BufferSize; // 一次传输数据个数
uint32_t DMA_PeripheralInc; // 外设地址自增使能
uint32_t DMA_MemoryInc; // 存储器地址自增使能
uint32_t DMA_PeripheralDataSize; // 外设数据位宽
uint32_t DMA_MemoryDataSize; // 存储器数据位宽
uint32_t DMA_Mode; // 模式：普通模式 / 循环模式
uint32_t DMA_Priority; // 数据流软件优先级
uint32_t DMA_FIFOMode; // FIFO模式使能 / 直接模式
uint32_t DMA_FIFOThreshold; // FIFO触发阈值
uint32_t DMA_MemoryBurst; // 存储器突发传输
uint32_t DMA_PeripheralBurst; // 外设突发传输
}DMA_InitTypeDef;
逐个成员讲解

  1. DMA_Channel
    选择该Stream对应的外设通道，用来映射硬件外设请求（USART/ADC/SPI等）。
    重点：M2M（存储器到存储器）传输，没有外设硬件请求，此参数无效，可任意填写。
  2. DMA_PeripheralBaseAddr
    外设一侧起始地址
    • M2P：外设寄存器地址（例如 &USART1->DR）
    • M2M：把源地址填入此成员
  3. DMA_Memory0BaseAddr
    存储器起始地址
    • M2P：内存缓冲区首地址
    • M2M：目标内存地址
  4. DMA_DIR 传输方向（三大模式）
    • DMA_DIR_PeripheralToMemory：外设 → 存储器（P2M，ADC采集常用）
    • DMA_DIR_MemoryToPeripheral：存储器 → 外设（M2P，串口DMA发送）
    • DMA_DIR_MemoryToMemory：存储器 → 存储器（M2M，FLASH→SRAM，F4仅DMA2支持）
  5. DMA_BufferSize
    本次DMA需要搬运多少个数据单元，最大65535，每启动一次传输，CNDTR寄存器装载这个数值
  6. DMA_PeripheralInc 外设地址自增
    • DMA_PeripheralInc_Enable：每传输一个数据，外设地址自动+位宽
    • DMA_PeripheralInc_Disable：地址固定（串口DR寄存器必须关闭自增！）
  7. DMA_MemoryInc 存储器地址自增
    缓冲区数组必须开启自增；如果只读写单个变量，可以关闭
  8. DMA_PeripheralDataSize / DMA_MemoryDataSize
    可选：DMA_PeripheralDataSize_Byte(8bit) / HalfWord(16bit) / Word(32bit)
    两边位宽可以不一致，DMA硬件自动完成位宽转换
  9. DMA_Mode 工作模式
    • DMA_Mode_Normal普通模式：传输完成一次后，DMA停止，需要软件重新使能才能再次传输
    • DMA_Mode_Circular循环模式：传输完成后自动重装长度，持续循环传输（音频、持续采样场景）
    限制：M2M模式不支持循环模式！
  10. DMA_Priority
    数据流优先级：高/中/低/极低；多条Stream同时传输时，仲裁器以此作为调度依据
  11. DMA_FIFOMode FIFO模式
    • DMA_FIFOMode_Enable：开启4级FIFO缓冲
    • DMA_FIFOMode_Disable：直接模式，收到数据立刻搬运
    硬性规则：M2M传输强制只能使用直接模式，必须关闭FIFO！
  12. DMA_FIFOThreshold
    FIFO缓存积累到多少数据后开始批量传输，仅开启FIFO时生效
  13. DMA_MemoryBurst / DMA_PeripheralBurst 突发传输
    批量总线突发访问，初学实验一般配置 DMA_MemoryBurst_Single（单次传输），不用开启突发

二、两种传输模式：M to M 和 M to P 完整讲解
1、 M to M 【存储器到存储器】 FLASH → SRAM
含义
源地址、目标地址都属于芯片内存区域（FLASH、SRAM），不需要外部外设触发请求，软件直接启动DMA搬运
典型用途：批量拷贝常量、大数组；
硬件限制：STM32F4只有DMA2控制器支持M2M，DMA1不支持！
M-M 五步编程要点

  1. 定义两块存储区域
    • FLASH端：const uint8_t src_buf[] = {xxx};
    const修饰，编译器自动把数组存放于FLASH。
    • SRAM端：uint8_t dst_buf[sizeof(src_buf)];
    运行时存放拷贝结果。
  2. 选定DMA资源
    必须选用DMA2，任选一条Stream；定义宏方便后期修改控制器、流编号
  3. 配置DMA_InitTypeDef结构体（重点差异）
    • DMA_DIR = DMA_DIR_MemoryToMemory
    • FIFO必须关闭（直接模式）
    • 不支持循环模式
    • 外设地址填写源FLASH地址，内存地址填写目标SRAM地址
    • 外设地址自增、内存地址自增同时开启
  4. 编写数据比较函数
    DMA传输完成后，对比src_buf与dst_buf内容，判断拷贝是否成功
  5. main函数逻辑
    开启DMA数据流 → 等待传输完成标志TCIF → 关闭DMA → 调用比较函数验证结果
    通俗原理
    CPU触发启动DMA，之后无需干预；DMA直接通过AHB总线，把FLASH的数据一块块搬运到SRAM

2、M to P 【存储器到外设】 SRAM → 串口
含义
内存SRAM缓冲区的数据，由外设硬件请求触发DMA自动搬运到外设寄存器
课件实验：SRAM数组 → USART1数据寄存器DR，串口向外发送；同时主循环控制LED闪烁
实验目的直观证明：DMA搬运数据期间，CPU可以同时执行别的任务（点灯），不被占用！
M-P 三步编程要点

  1. 初始化串口外设
    移植成熟的USART初始化代码；删除串口中断相关代码
    DMA模式依靠硬件发送请求，不需要接收/发送中断
  2. 配置DMA_InitTypeDef结构体（重点差异）
    • DMA_DIR = DMA_DIR_MemoryToPeripheral
    • 外设地址：&USART1->DR（串口数据寄存器）
    • 外设地址自增：关闭！DR寄存器地址固定不变
    • 存储器地址自增：开启（数组依次取出数据）
    • 根据需求选择普通模式/循环模式；支持开启FIFO
  3. main函数逻辑
    准备待发送数组 → 初始化DMA、串口 → 使能DMA数据流 → 使能串口DMA发送请求
    主循环持续翻转LED，观察：串口不断打印数据，LED同时持续闪烁
    核心现象解读
    如果不使用DMA：CPU需要循环调用发送函数，等待每一字节发送完成，CPU被死死占用，很难同时稳定点灯
    使用DMA：硬件自动搬运字节，CPU解放出来独立运行点灯逻辑

三、M-M 与 M-P 关键区别汇总
项目 M2M(存储器到存储器) M2P(存储器到外设)
触发方式 软件主动启动DMA 外设硬件请求触发（TXE标志）
可用控制器 仅DMA2 DMA1、DMA2都支持
FIFO 强制关闭，直接模式 可选开启FIFO
循环模式 不支持 支持
典型应用 内存大批量数据拷贝 串口、SPI、DAC自动发送

四、初学高频易错

  1. M-M不能用DMA1，会导致一直传输失败；
  2. M-M不能开循环模式、不能开FIFO；
  3. M-P串口DMA发送，外设地址自增必须关闭；
  4. 不要混淆：通道只是外设映射，Stream流才是独立传输单元；
  5. DMA启动之后，CPU只是“发起命令”，搬运全程硬件自主执行
