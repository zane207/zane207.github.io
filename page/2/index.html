GPIO按键检测实操总结

使用固件库编写代码的执行顺序都分为三部

一、 初始化配置：KEY_GPIO_Config 函数

这部分对应理论总结中的“软件配置三步曲”

  1. 开启外设时钟
    RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_GPIOA|RCC_AHB1Periph_GPIOC, ENABLE);
    原理解析：STM32的时钟树设计是为了降低功耗。所有的外设（包括GPIO）默认都是关闭的，使用位或运算符 | 将 GPIOA 和 GPIOC 的时钟使能位合并，一次性开启，这在工程上是非常高效的写法
  2. 配置引脚模式与上下拉
    GPIO_InitStruct.GPIO_Pin = GPIO_Pin_0;
    GPIO_InitStruct.GPIO_Mode = GPIO_Mode_IN;
    GPIO_InitStruct.GPIO_PuPd = GPIO_PuPd_NOPULL;
    GPIO_Init(GPIOA, &GPIO_InitStruct);
    原理解析：这里将 PA0 和 PC13 配置为输入模式
  • 关键工程提醒： GPIO_PuPd_NOPULL（浮空输入），根据野火的理论总结：“硬件电路上，按键通常配合上拉或下拉电阻使用，目的是避免引脚悬空导致状态混乱”
  • 如果外部没有电阻，必须改成 GPIO_PuPd_UP（上拉输入）或 GPIO_PuPd_DOWN（下拉输入），否则引脚处于不确定状态，会导致按键失灵或误触发

二、 按键扫描逻辑：KEY_Scan 函数
这部分对应理论总结中的“逻辑判断”与“防误触机制”
uint8_t KEY_Scan(GPIO_TypeDef *GPIOx,uint16_t GPIO_Pin)
{
if(GPIO_ReadInputDataBit(GPIOx, GPIO_Pin)== KEY_ON )
{
while(GPIO_ReadInputDataBit(GPIOx, GPIO_Pin)== KEY_ON);
return KEY_ON;
}
else return KEY_OFF;
}

  1. 状态读取与判断
  • GPIO_ReadInputDataBit 是标准库函数，直接读取输入数据寄存器（IDR）的对应位，通过判断返回值是否等于宏定义的 KEY_ON，来确定按键是否触发
  1. 阻塞式等待（松手检测）
  • while(GPIO_ReadInputDataBit(…) == KEY_ON); 这是一个阻塞式（Blocking）的死循环
  • 工程意义：它的目的是实现“单次触发”逻辑。只要用户的手指没有离开按键，程序就会一直卡在这个 while 循环里，不会返回 KEY_ON。只有松开按键，电平恢复，才会跳出循环并返回信。这避免了“长按导致LED疯狂闪烁”的问题

三、 主程序逻辑：main 函数
while (1)
{
if( KEY_Scan(GPIOA,GPIO_Pin_0) ==KEY_ON )
{
LED1_TOGGLE;
}

}

  • 原理解析：这是典型的轮询（Polling）架构。单片机在 while(1) 中不断调用 KEY_Scan

手动搭建GPIO函数库函数雏形.2

这次做寄存器映射中的结构体映射
结构体映射要从：
1.定义基础类型
2.建立结构体映射
3.用指针配合结构体
4.使用 BSRR 寄存器来拉高/拉低电平

一、 为什么要定义基础类型（typedef）？
代码片段：
typedef unsigned char uint8_t;
typedef unsigned int uint32_t;
原因：跨平台与硬件的“绝对对齐”

  1. C语言的“不严谨”：在标准 C 语言中，int 到底是 16位、32位还是 64位，取决于你的编译器（比如 PC 上的 GCC 和单片机上的 ARMCC 是不同的）。
  2. 硬件的“强迫症”：STM32 的寄存器是严格的 32位（4字节）或 8位。如果你用 int 去操作一个本该是 32位的寄存器，在某些编译器下可能只分配了 16位，导致你写入的数据被截断，或者覆盖了旁边的其他寄存器。
  3. 结论：通过 typedef 强制规定 uint32_t 就是 32位无符号整数，确保代码在任何编译器下，对内存的读写长度都是绝对一致的

二、
为什么要用结构体（struct）来映射寄存器？
代码片段：
typedef struct {
volatile uint32_t MODER; // 偏移 0x00
volatile uint32_t OTYPER; // 偏移 0x04
// …
} GPIO_RegDef_t;
原因：将“冰冷的地址”变成“有逻辑的变量”

  1. 内存的连续性：STM32 的 GPIOA 的所有寄存器在物理内存中是紧挨着的（从 0x40020000 开始，每隔 4 个字节一个）。C 语言的结构体在内存中也是连续分配的
  2. 告别魔法数字（Magic Number）：
    • 如果不用结构体，你要配置模式，得写：(volatile uint32_t)(0x40020000 + 0x00) = xxx;
    • 配置速度得写：(volatile uint32_t)(0x40020000 + 0x08) = xxx;
    • 这种代码极难维护，一旦基地址变了，要改几十处
  3. 结构体的优雅：定义好结构体后，编译器会自动帮你计算偏移量。你只需要写 pGPIOx->OSPEEDR = xxx;，编译器会自动翻译成 基地址 + 0x08。代码可读性极强，且完美契合芯片手册的寄存器表格
    关键补充：volatile 关键字的作用
    注意结构体里的 volatile。它告诉编译器：“这个变量的值可能会在程序之外被改变（被硬件改变），请不要自作聪明把它优化到 CPU 寄存器里，每次都必须老老实实去内存（物理地址）里读取！” 如果没有它，你的代码在开启编译优化（如 -O2）时会彻底失效

三、 为什么要用指针（Pointer）？
代码片段：
define GPIOA ((GPIO_RegDef_t*)GPIOA_BASE)
void My_GPIO_Init(GPIO_RegDef_t *pGPIOx, GPIO_InitTypeDef *pGPIOInit);
原因：实现代码的“高度复用”

  1. 硬件的对称性：STM32 有 GPIOA, GPIOB, GPIOC… 它们的内部寄存器结构（MODER, OTYPER等）是一模一样的，仅仅是基地址不同
  2. 指针的魔力：如果我们把函数的参数写成 GPIO_RegDef_t *pGPIOx（一个指向 GPIO 结构体的指针），那么：
    • 传 GPIOA 进去，它就操作 GPIOA 的寄存器
    • 传 GPIOB 进去，它就操作 GPIOB 的寄存器
  3. 结论：通过指针，你只需要写一套初始化函数，就能控制芯片上的几十个 GPIO 端口。这就是底层驱动框架设计的核心思想。

四、 为什么要用 BSRR 寄存器来拉高/拉低电平？
代码片段：
// 拉高：低 16 位置 1
GPIOA->BSRR = (1 BSRR = (1 ODR |= (1 ODR 步骤2：在 CPU 内部修改第 14 位 -> 步骤3. 把新值写回 ODR))))
如果在步骤2和步骤3之间，发生了中断，并且中断里也修改了 GPIOA 的其他引脚，那么中断返回后，步骤3.会把中断里的修改直接覆盖掉！这就叫“非原子操作”，极易引发隐蔽的 Bug
2. BSRR 的完美设计（原子操作）：
BSRR（Bit Set/Reset Register）是一个只写寄存器，硬件为它设计了特殊的逻辑：

  • 低 16 位 (0~15)：写 1 会将 ODR 对应位置 1（拉高），写 0 无效
  • 高 16 位 (16~31)：写 1 会将 ODR 对应位置 0（拉低），写 0 无效

优势：你只需要一条赋值语句（一条汇编指令 STR），硬件直接在内部完成“置位”或“清零”，不需要读-改-写的过程。这被称为原子操作，即使在最高优先级的中断里操作 BSRR，也绝对不会影响其他引脚的状态

总结：

  • 基础类型保证了数据宽度的绝对正确；
  • 结构体把物理地址变成了优雅的代码；
  • 指针让一套代码控制了所有外设；
  • BSRR 则利用硬件特性，保证了电平翻转的绝对安全与高效

STM32f407GPIO寄存器实操笔记

第一
1、片上外设基地址
ST生产STM32的时候，给芯片里面所有外设安排独一无二的地址，就像每家的门牌号。
所有外设统一从 0x40000000 开始，这个把它取为：PERIPH_BASE
#define PERIPH_BASE ((unsigned int)0x40000000)
理解：整个小区大门地址：0x40000000
2、区分不同总线：AHB1总线偏移
芯片内部有好几条“（总线）”
GPIOA/GPIOB/GPIOF全部跑在 AHB1
厂家规定：AHB1 = PERIPH_BASE + 0x20000
#define AHB1PERIPH_BASE (PERIPH_BASE + 0x00020000)
理解：AHB1这条街道入口 = 大门往里走0x20000
3、GPIOA的门牌号
GPIOA就在AHB1街道最开头，偏移0，所以：
#define GPIOA_BASE (AHB1PERIPH_BASE + 0x0000)
GPIOF是 AHB1PERIPH_BASE + 0x1400，相当于同一条街往后走一段距离。
4、GPIOA里面一堆寄存器，靠【偏移量】区分
找到GPIOA大门（GPIOA_BASE）之后，门里面有一排连续房间，每个房间对应一个寄存器：
厂家手册固定死偏移：
• MODER 模式寄存器：进门第0间 → +0x00
• OTYPER 输出类型：第1间 → +0x04
• OSPEEDR速度寄存器：+0x08
• PUPDR上下拉：+0x0C
• IDR输入寄存器：+0x10
• ODR输出寄存器：+0x14
• BSRR置位/复位寄存器：+0x18
代码里这句含义：
#define GPIOA_MODER (unsigned int)(GPIOA_BASE+0x00)

  1. GPIOA_BASE+0x00：算出MODER房间地址
  2. (unsigned int *)：把数字强行变成地址指针
  3. 最前面*：代表去这个地址里面读写数据

第二：2*5、1<<5 这些数字怎么来（PA5引脚）
每个引脚都分配固定的bit位置
1.MODER、OSPEEDR、PUPDR：每个引脚占用 2个bit！！重点！
PA0 → bit0、bit1
PA1 → bit2、bit3
PA2 → bit4、bit5
……
PA5 → bit10、bit11
计算公式：引脚编号 × 2
PA5：5 * 2 =10，从第10位开始占用两位
GPIOA_MODER &= ~((unsigned int)0x3 << (2 * 5));
0x3 = 二进制11，代表连续两个1；向左移10位，刚好对准PA5的两个bit。

2.OTYPER、BSRR、IDR、ODR：每个引脚只占用 1个bit
PA5就只用第5号位，不用乘2
GPIOA_OTYPER &= ~(0x1 << 5);
GPIOA_BSRR |= (1 << 5);
1 << 5 = 二进制 100000，第5位是1，精准选中PA5

3.BSRR特殊规则（一定要记住）
• 低16位（bit015）写1 → 引脚变高电平
• 高16位（bit1631）写1 → 引脚变低电平
PA5拉低写法：1 << (16+5)

第三点：函数里每一步的逻辑通俗解释
RCC_AHB1ENR |= (1 << 0);
RCC是时钟总开关。GPIOA挂在AHB1第0位。
= 给GPIOA“通电”，不通电寄存器全部失灵，相当于设备没插电。
GPIOA_PUPDR |= ((unsigned int)0x01 << (2 * 5));
01=内部上拉。PA5上电默认被内部电阻拉到3.3V；
如果你不想上下拉，就只写清零那一行，不要加这一句。
PA5 普通引脚：随便配置，不用额外代码
PA13 PA14 PA15：出厂默认分给下载器JTAG，就算地址代码写对，硬件会抢控制权，必须SYSCFG解除占用，PA5没有这个麻烦！
极简记忆口诀

  1. 地址：大门基地址 + 寄存器固定偏移
  2. 2bit寄存器(MODER/速度/上下拉)：移位 = 引脚×2
  3. 1bit寄存器(OTYPER/BSRR)：直接 1 << 引脚号
  4. 第一步永远先开时钟！不开时钟一切配置白费

#define GPIOF_BASE (AHB1PERIPH_BASE + 0x1400)

写寄存器代码的前提 第1行：RCC_AHB1ENR |= (1 << 0);
课本知识没有写，但一切GPIO的前提
GPIO相当于电器，时钟=电源。不开时钟，后面所有寄存器全部失效。
GPIOA在AHB1时钟寄存器第0位，写1=通电。

第四. GPIOA_MODER（模式寄存器）
理论规则：
MODERy[1:0]
00：输入（上电默认）
01：通用输出
10：复用功能
11：模拟输入
代码：
GPIOA_MODER &= ~((unsigned int)0x3 << (2 * 5));
GPIOA_MODER |= ((unsigned int)0x1 << (2 * 5));

  1. PA5，y=5；MODER每个引脚占用2位 → 移位 2*5=10
  2. 0x3 = 二进制 11
    &= ~(0x3 <<10)：先把PA5对应的两位清0，清除上电默认配置
  3. 0x1 = 二进制 01，写入进去
    最终效果：PA5 设置【通用输出模式】

第五. GPIOA_OTYPER（输出类型寄存器）
理论规则：
0：推挽输出（复位默认）
1：开漏输出
代码：
GPIOA_OTYPER &= ~(0x1 << 5);
OTYPER每个引脚只占1个位，直接1<<引脚号
~(1<<5) 把第5位清0
PA5配置成【推挽输出】
推挽：能主动输出3.3V高电平、0V低电平，最常用驱动LED

第六. GPIOA_OSPEEDR（输出速度寄存器）
理论规则：
00：2MHz
01：25MHz
10：50MHz
11：100MHz
代码：
GPIOA_OSPEEDR &= ~((unsigned int)0x03 << (2 * 5));
GPIOA_OSPEEDR |= ((unsigned int)0x00 << (2 * 5));
OSPEEDR和MODER一样，每个引脚2位，移位 = 引脚×2
先清零两位，再写入00
PA5 最大速度 2MHz（低速）
日常点灯用低速足够，省电、噪声小

第七. GPIOA_PUPDR（上下拉寄存器）
理论规则：
00：无上下拉
01：上拉
10：下拉
11：保留
代码：
GPIOA_PUPDR &= ~((unsigned int)0x03 << (2 * 5));
GPIOA_PUPDR |= ((unsigned int)0x01 << (2 * 5));
PUPDR依旧是每个引脚占用2位
先清零，写入二进制01
PA5开启【内部上拉电阻】
小提醒：输出模式开上拉一般很少用，输入模式用得多。如果只是驱动LED，可以删掉这一行，改成只清零 GPIOA_PUPDR &= ~((unsigned int)0x03 << (2 * 5)); 设置成无上下拉

第八. GPIOA_BSRR（置位/复位寄存器）
理论规则：
BSRR低16位 BSy：写1 → 引脚置高电平
BSRR高16位 BRy：写1 → 引脚置低电平
代码：
GPIOA_BSRR |= (1 << 5);
1<<5，对应BS5位写1
PA5立即输出高电平（3.3V）

如果想要拉低，写法：
GPIOA_BSRR |= (1U << (16 + 5));
重点区分 BSRR 和 ODR

BSRR 优势：只修改指定引脚，不会影响其他IO，强烈推荐；
不要直接写 GPIOA_ODR，多任务下容易冲突。
整体总结：这段代码最终配置结果

PA5：通用推挽输出、2MHz低速、内部上拉、上电直接输出高电平

万能公式
MODER / OSPEEDR / PUPDR（2位寄存器）
寄存器 &= ~(0x3 << (2 * 引脚号)); //清空
寄存器 |= (值 << (2 * 引脚号)); //写入配置
OTYPER / BSRR / IDR / ODR（1位寄存器）
寄存器 &= ~(1 << 引脚号);
寄存器 |= (1 << 引脚号);

易错点
PA13、PA14、PA15：硬件默认JTAG调试功能
MODER配置会被硬件强行覆盖，就算代码写的一模一样，引脚不受控制，必须用SYSCFG解除复用
PA5/PA0~PA12：普通引脚，直接这套代码就能正常运行，没有额外限制

整体代码：
void PA5_Init_F407_Reg(void)
{
/* 1. 开启 GPIOA 时钟 (AHB1ENR 的第 0 位) */
RCC_AHB1ENR |= (1 << 0); 

/* 2. MODER寄存器 配置PA5 */
GPIOA_MODER &= ~((unsigned int)0x3 << (2 * 5)); 
GPIOA_MODER |= ((unsigned int)0x1 << (2 * 5));  

/* 3. OTYPER 输出类型 */
GPIOA_OTYPER &= ~(0x1 << 5); 

/* 4. OSPEEDR 输出速度 */
GPIOA_OSPEEDR &= ~((unsigned int)0x03 << (2 * 5));
GPIOA_OSPEEDR |= ((unsigned int)0x00 << (2 * 5)); 

/* 5. PUPDR 上下拉配置 */
GPIOA_PUPDR &= ~((unsigned int)0x03 << (2 * 5));
GPIOA_PUPDR |= ((unsigned int)0x01 << (2 * 5));   

/* 6. BSRR 设置PA5输出高电平 */
GPIOA_BSRR |= (1 << 5);

while(1);

}

C语言运算知识

一.原码，反码，补码
电脑/单片机只认识二进制 0 和 1，数字分正数、负数，机器靠最高一位区分正负：
最高位=0 → 正数
最高位=1 → 负数
我们拿1字节（8位二进制）举例，好理解。

  1. 原码：给人看得懂的写法
    规则：
    最高位符号位，后面正常写数字二进制。
    举例8位：
    +5：00000101 （0代表正数）
    -5：10000101 （1代表负数）
    缺点：
    0有两种写法：00000000（+0）、10000000（-0），重复浪费空间
    计算机做减法巨麻烦，硬件不好计算，所以机器不用原码运算

  2. 反码：过渡产物，只为算补码用
    规则：
    正数：反码 = 原码（不变）
    负数：符号位不动，剩下所有0变1、1变0
    还用8位举例：
    +5 原码：00000101 → 反码不变：00000101
    -5 原码：10000101 → 符号1不动，后面取反 → 11111010
    缺点：
    0还是有两个表示，依旧不能直接拿来做减法，只是中间步骤。
    3=（-2）= 00000011+11111101=1 000000000（多一位）

  3. 补码：计算机真正存数字、算数字的格式（重点！）
    规则
    正数：补码 = 原码 = 反码，全程不变
    负数：负数反码 + 1 = 补码
    举例 -5
    原码：10000101
    反码：11111010
    反码+1 → 补码：11111011

为什么一定要用补码？两大好处
解决0重复问题，8位二进制只有一个0：00000000
举个例子：计算 5 - 3 = 5 + (-3)
5补码：00000101
-3补码：11111101
两者相加：00000010 也就是2，计算正确！

极简记忆口诀
原码：人看的，正负分开写
反码：负数符号不动，其余全部翻转
补码：正数原样，负数反码加1；电脑存数字、算加减全靠它因此计算机内部用补码=

二.位运算与位运算符
单片机、电脑里所有数字底层都是二进制0、1
位运算 = 直接操作整数类型的二进制里每一个0和1，嵌入式写寄存器、控制引脚

位运算符有6个

  1. 按位与 & （符号：和）
    规则：两位同时为1，结果才是1；只要有一个0，结果就是0
    口诀：全1才1，有0则0
    例：3 & 1
    3二进制：00000011
    1二进制：00000001
    结果：00000001 = 1
    嵌入式用途：清零某一位、读取寄存器某一个引脚状态

  2. 按位或 | （符号：竖线）
    规则：任意一位是1，结果就是1；全0才是0
    口诀：有1则1，全0才0
    例：3 | 1
    00000011 | 00000001 = 00000011 =3
    嵌入式用途：把指定某一位置1（拉高引脚电平）

  3. 按位异或 ^
    规则：两位不一样=1，两位相同=0
    口诀：相同出0，不同出1
    例：3 ^ 1
    00000011 ^ 00000001 = 00000010 =2
    用途：翻转指定二进制位、简单加密、交换数字不用第三方变量

  4. 按位取反 ~ （单目运算符，只写在数字前面）
    规则：所有0变1，所有1变0，符号位也一起翻转
    例：char a=3（00000011）
    ~a 全部翻转 = 11111100
    重点：单片机char是有符号数，最高位1代表负数，取反后会变成负数。
    用途：批量清零多位寄存器

  5. 按位左移 <<
    格式：数字 << 移动位数
    规则：二进制整体往左挤，右边空出来补0，左边挤出去的数字直接丢掉
    例：1 << 2
    1：00000001
    左移2位：00000100 等于4
    隐藏技巧：左移n位 = 数字 × 2的n次方

  6. 按位右移 >>
    格式：数字 >> 移动位数
    分两种情况：

  7. 正数：整体右挤，左边补0

  8. 负数（补码存储）：整体右挤，左边补1
    例：4 >> 1
    4：00000100 → 右移1位 00000010 =2
    —4 >> 1
    —4：11111100 → 右移1位 11111110 =—2
    隐藏技巧：右移n位 = 数字 ÷ 2的n次方（取整数）

嵌入式最常用组合操作（写寄存器必用）

  1. 某一位置1：a |= (1<<n)
  2. 某一位清零：a &= ~(1<<n)
  3. 翻转某一位：a ^= (1<<n)
    总结
  4. & 留1清0；| 统一置1；^ 相同归零
  5. ~ 全部翻转；<< 左移翻倍；>> 右移减半
  6. 单片机控制引脚、配置寄存器全部靠位运算，不会改动其他引脚，精准控制单独某一位

三.复合赋值运算符

普通写法：a = a + 数字
意思是：拿a本身的值，加上一个数，算完之后，结果重新存回a里面。
复合赋值就是把这行代码简写，少敲重复的a，写单片机代码经常用。
复合赋值运算符:将运算和赋值合并为一步的简写方式
逐个讲常用6种，配简单例子
我们统一设初始值：int a = 5;

  1. 加法复合 +=
    简写 a += 3 等价完整写法 a = a + 3
    计算：5+3=8，最后a=8
  2. 减法复合 -=
    简写 a -= 2 等价 a = a - 2
    初始a=5，5-2=3，最后a=3
  3. 乘法复合 *=
    简写 a = 4 等价 a = a * 4
    5    4=20，a变成20
  4. 除法复合 /=
    简写 a /= 2 等价 a = a / 2
    5÷2=2（整数只留整数部分），a=2
  5. 取余复合 %=
    简写 a %= 2 等价 a = a % 2
    5除以2余1，a=1
  6. 位运算复合（单片机写寄存器天天用！重点）
  7. a |= (1<<2) 等价 a = a | (1<<2) 单独把第2位置1
  8. a &= ~(1<<3) 等价 a = a & ~(1<<3) 单独把第3位清零
  9. a ^= (1<<1) 等价 a = a ^ (1<<1) 翻转第1位电平
  10. a <<= 1 等价 a = a << 1 左移一位翻倍
  11. a >>= 1 等价 a = a >> 1 右移一位除以2

核心记忆口诀
符号= 等于 自己 符号 数字
举个万能模板：a OP= b ↔ a = a OP b
OP就是 + - * / % & | ^ << >> 任意运算符

易错点

  1. 复合运算符中间不能加空格，不能写成 a + = 3，正确 a +=3
  2. 等号永远在运算符右边，顺序别写反，没有 =+ 这种写法！

嵌入式实用例子（控制引脚）
unsigned int GPIOA = 0;
GPIOA |= (1<<15); // PA15引脚置高
GPIOA &= ~(1<<15); // PA15引脚清零
用复合写法代码更短，是写STM32寄存器标准写法。

一：外设寄存器结构体定义
核心思想：
在之前的课程中，操作一个GPIO引脚需要记住基地址和偏移地址（如 0x40021400+0x00），这非常容易出错。这节课引入了编程学习中结构体（struct），将属于同一个外设（如GPIOF）的所有寄存器打包在一起。通过指针强转，我们可以用 -> 语法直观地访问各个寄存器。

关键代码：
// 1. 定义GPIO外设的结构体，严格按照数据手册的寄存器顺序排列
typedef unsigened int uint32_t;
typedef unsigened short int uint16_t;
typedef struct
{
uint32_t MODER; // 模式寄存器 (偏移量: 0x00)
uint32_t OTYPER; // 输出类型寄存器 (偏移量: 0x04)
uint32_t OSPEEDR; // 输出速度寄存器 (偏移量: 0x08)
uint32_t PUPDR; // 上下拉寄存器 (偏移量: 0x0C)
uint32_t IDR; // 输入数据寄存器 (偏移量: 0x10)
uint32_t ODR; // 输出数据寄存器 (偏移量: 0x14)
uint16_t BSRRL/H; // 置位/复位寄存器 (偏移量: 0x18)
uint32_t LCKR; // 配置锁定寄存器 (偏移量: 0x1C)
uint32_t AFRL/H; // 复用低/高功能寄存器 (偏移量: 0x20, 0x24)
} GPIO_TypeDef;

// 2. 利用宏定义，将结构体指针绑定到具体的硬件基地址上
define GPIOF_BASE (( unsigned int )0x40021400)
define GPIOF (GPIO_TypeDef *)GPIOF_BASE

二：编写端口复位和置位函数
核心思想：
封装好结构体后，接下来把常用的操作（如点亮、熄灭LED）封装成函数。这样在 main.c 中调用时，代码的可读性会大幅提升，不再需要写冗长的位操作（&= ~ 或 |=）。

关键代码：
// 置位函数（输出高电平）
void GPIO_SetBits(GPIO_TypeDef* GPIOx, uint16_t GPIO_Pin)
{
GPIOx->BSRRL = GPIO_Pin; // 向低16位写1，对应引脚输出高电平
}

// 复位函数（输出低电平）
void GPIO_ResetBits(GPIO_TypeDef* GPIOx, uint16_t GPIO_Pin)
{
GPIOx->BSRRH = GPIO_Pin; // 向高16位写1，对应引脚输出低电平
}
// 在main函数中调用变得非常简洁：
// GPIO_SetBits(GPIOF, GPIO_Pin_6);

核心思想：
为了避免初始化函数出现“参数爆炸”（即函数括号里需要传入十几个参数），引入了初始化配置结构体。将引脚、模式、速度等配置打包，通过指针一次性传给初始化函数。

关键代码：

{

#关于scanf,typedef

一.scanf 是干嘛的？

scanf = 让程序等待你从键盘打字输入数字/文字，把你敲的内容存到变量里。
没有它程序只会自己跑，有了它你能手动给程序填数据。

类比：
程序是收银机，printf 是屏幕提示“请输入金额”，scanf 就是读取你按键盘输的数字。

固定格式（死记就行）0=
scanf(“格式符号”, &变量名);
两个必懂关键点：

二.格式符号：告诉程序你要输入什么类型数据

%d = 整数（年龄、数字）

%f = 小数（身高、价格）

%s = 一串文字（姓名、单词，不带空格）

& 取地址符号：除了数组，普通变量前面必须加！
大白话：& 就是告诉程序“把你输入的东西放到这个变量的内存盒子里”

最简单完整例子（输入年龄）
#include <stdio.h>
int main()
{
int age; // 造一个盒子age，装整数
printf(“请输入你的年龄：”); // 提示文字
scanf(“%d”, &age); // 等待键盘输入数字，存进age
printf(“你今年%d岁”, age); // 打印你输入的数字
return 0;
}
运行流程：

  1. 屏幕弹出：请输入你的年龄：

  2. 你键盘敲 18，按回车

  3. 18 自动装进 age 变量

  4. 屏幕输出：你今年18岁

分类型举例，一看就会

输入整数 %d
int num;
scanf(“%d”, &num);
输入小数 %f
float height;
scanf(“%f”, &height);
输入名字（字符数组，不用加&！重点）

之前结构体的 char name[20] 就是数组，数组名字本身自带地址，不许写&
char name[20];
scanf(“%s”, name); // 没有&！
三.初学者最容易踩的3个坑

坑1：普通变量忘记写 &

错误：scanf(“%d”, age);
正确：scanf(“%d”, &age);
不写&程序会直接崩溃乱码。

坑2：给文字数组多加了&

错误：scanf(“%s”, &name);
正确：scanf(“%s”, name);
数组自带地址，加&反而报错。

坑3：输入带空格的文字读不全

scanf(“%s”) 遇到空格就停止读取
比如你输入 zheng jiawei，它只会存 zhang，后面文字直接丢掉。

四.typedef到底是干嘛的？

直译：类型重命名
大白话：给复杂的数据类型起一个简短好写的外号，少打字、不容易写错。

对比不用typedef 和 用typedef 的区别（拿结构体举例）

1.不使用typedef（原生写法，每次都要写struct）
struct Student{
char name[20];
int age;
};
// 创建变量必须完整写 struct Student
struct Student s1;
struct Student s2;
缺点：每次新建学生变量，都要带上 struct 四个字，代码长、麻烦。

2.使用typedef（起外号 Stu）
// typedef + 原类型 + 新外号
typedef struct Student{
char name[20];
int age;
} Stu;
// 直接用外号创建变量，不用写struct
Stu s1;
Stu s2;
拆解这句：
typedef struct Student = 原来完整的类型名
Stu = 我们给它起的简短外号

3.通用万能公式（所有类型都能用typedef）
typedef 原来的类型 新名字;
示例1：给int起外号（简单类型也能用）
typedef int Num;
Num a = 18; // 等价于 int a = 18;
示例2：给float起外号
typedef float Score;
Score math = 95.5;
4.初学者最容易记混的关键点

5.typedef 不会创造新类型，只是换个名字，底层还是原来的struct/int/float；

62.结构体搭配typedef是写代码最常用场景，专门简化变量定义；

7.顺序不能写反：typedef 原名 外号，不能反过来。

五.scanf与typedef和之前结构体结合的完整实操代码
#include <stdio.h>
#include <string.h>

typedef struct Student{
char name[20];
int age;
} Stu;

int main()
{
Stu s1;
// 输入姓名
printf(“请输入学生姓名：”);
scanf(“%s”, s1.name);
// 输入年龄
printf(“请输入学生年龄：”);
scanf(“%d”, &s1.age);
// 打印读取到的数据
printf(“学生：%s，年龄：%d”, s1.name, s1.age);
return 0;
}
运行后你手动输入名字、年龄，程序就能读取并存进结构体里。

极简总结

  1. scanf 用来读取键盘输入；

  2. 数字/小数变量前面必须加 &；

  3. char 文字数组不用加 &；

  4. %d存整数，%f存小数，%s存文字。

C语言结构体笔记

#关于结构体
一、结构体是干嘛的？

普通变量只能存单个数据：int年龄、char姓名、float分数。
结构体 = 自己造一个复合盒子，把同一个人的多种信息打包放一起。
比如学生：姓名、年龄、分数、班级，全部塞进一个结构体。

二、结构体的定义

struct:释义： （名词）结构；结构体；构架；组织；体系 （动词）使形成体系；
struct结构体类型名
{
数据类型 成员名;
数据类型 成员名;
……
};
定义结构体的方法
1.先定义结构体类型，再定义结构体变量 （可定义局部或全局的结构体变量）
例：
struct Student
{
char name[20]; //姓名
int age; //年龄
float score; //成绩
}；

struct Student s1,s2;（可定义多个变量）

2.定义结构体的同时，定义结构体的变量 （可定义全局的结构体变量）
例：
struct Student
{
char name[20]; //姓名
